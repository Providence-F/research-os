# 行文思路规划协议（v2.0 重构：叙事原型）

> v2.0 核心重构。解决 v1.x"一套行文思路打天下"的模板化僵化问题。
> 核心机制从"三级节点提纲法"升级为 **6 种叙事原型（archetype）**：按调研主体 × 意图类型选择认知路径。
> 此步骤在 step_7（多 Agent 分析）之后、step_8（反方审计）之前执行，产出 `05-analysis/narrative-plan.md`。
> 最终报告（step_9）必须遵循此规划。

---

## 1. 为什么需要原型

v1.x 的问题是：系统规定了"认知递进元原则"，但所有调研主体（公司/产品/技术概念/行业/人物）共用一套递进形状。结果：

- 技术概念科普按"公司调研"的形状写，读者在地基没打好时被抛入竞争分析
- 用户研究按"产品拆解"的形状写，原声被塞进"差异化"章节失去冲击力
- Agent 每次自由发挥结构，质量取决于个体能力而非系统保障——自由度过大等于没有保障

v2.0 的解决思路：把"认知路径的形状"收敛为 6 种可枚举的原型。

**原型不是模板。** 原型定义"读者认知推进的路径形状"（先建立什么、再建立什么、张力在哪里），不定义内容、不规定章节标题措辞、不限制章节数量。同一个 product_teardown 原型，拆 Manus 和拆 Notion 的章节内容应该完全不同——相同的是认知推进的次序。

> **反模板警告（全局）**：禁止把原型当填空模板。如果某次调研中 Agent 发现自己只是"把内容塞进原型骨架"而没有做认知路径判断，说明原型选错了或正在被误用——回到选择矩阵重选，或在 why_not 中说明调整理由。

---

## 2. 原型选择规则

在 step_7.5 执行。选择依据 = **调研主体类型 × 意图类型（学习 / 决策）**。

### 选择矩阵

| 调研主体 \ 意图 | 学习（理解对象） | 决策（要不要做 X） |
|---|---|---|
| 技术概念 / 技术方案 | `learning_curve` | `learning_curve`（主）+ `decision_forum`（辅） |
| 公司 / 产品 | `product_teardown` | `decision_forum` |
| 行业 / 赛道 | `opportunity_map` | `opportunity_map`（主）+ `decision_forum`（辅） |
| 用户 / 人群 | `user_voice` | `user_voice`（主）+ `decision_forum`（辅） |
| 人物 / 复杂混合主体 | `mixed_journey` | `mixed_journey` |
| 开放问题（要不要做 X） | `decision_forum` | `decision_forum` |

选择规则：

1. 选择结果写入 `05-analysis/narrative-plan.md` 的 `archetype:` 字段
2. **必须写 `why_not:` 字段**——说明为什么排除次优原型（矩阵中同行/同列的次优候选）。why_not 不能为空，防止 Agent 默认选矩阵命中的第一个而不做判断
3. 意图类型依据：intent_doc.json 的 reader_model + task-card.md 的调研类型 + 深度档位（R0/R1 倾向决策，R2/R3 倾向学习或混合）

## 3. 六种原型

### 3.1 `learning_curve`（技术概念科普 · 学习意图）

- **适用场景**：调研主体是技术概念/技术方案（如"什么是 MCP""向量数据库怎么工作"），读者要从零建立理解
- **认知路径阶段**：已知（读者已有的日常经验）→ 桥梁（类比过渡）→ 未知（技术判断）的概念阶梯，逐阶抬升
- **章节骨架**：悬念（为什么这个概念值得懂）→ 地基（最少必要前置概念）→ 机制（它怎么工作）→ 边界（它不能做什么/什么时候失效）→ 地图（它在技术版图中的位置）
- **关键张力**：通俗性和准确性的配重——类比不能牺牲机制真相
- **反模板警告**：禁止把"悬念→地基→机制→边界→地图"当成五个填空槽。如果读者的前置知识已经覆盖了"地基"，地基章节应该坍缩；如果概念没有明显的能力边界争议，边界章节应该并入机制。骨架描述的是认知次序，不是章节配额。

### 3.2 `decision_forum`（决策意图 · 要不要做 X）

- **适用场景**：读者带着一个待定决策来（要不要加入这家公司 / 要不要采用这个技术 / 要不要进入这个赛道）
- **认知路径阶段**：问题（决策是什么、为什么现在必须定）→ 选项（有哪些真实选项，含"不做"）→ 判据（用什么标准比较）→ 裁决（结论与推理链）→ 风险（什么情况下裁决会错）
- **关键张力**：每个选项必须有最强论证（steelman）——被否决的选项也要先给出它的最佳形态再否决，禁止稻草人
- **反模板警告**：禁止"先定结论再补选项"的倒装写法。如果五个章节里"裁决"的篇幅超过"选项+判据"之和，说明这不是决策论坛而是结论宣讲——读者无法复现推理，裁决就没有可信度。

### 3.3 `product_teardown`（产品拆解）

- **适用场景**：调研主体是具体产品或公司（拆 Manus、拆 Notion、拆某家 SaaS）
- **认知路径阶段**：表象（用户看到什么、市场怎么定位）→ 机制（产品/技术/商业怎么运转）→ 壁垒（别人为什么抄不走）→ 演化（它从哪来、往哪去）→ 启示（对读者有什么用）
- **关键张力**：必须拆到"别人为什么抄不走"——拆到功能层是评测，拆到壁垒层才是拆解
- **反模板警告**：禁止把"壁垒"章节写成护城河名词罗列（网络效应/规模效应/转换成本各来一句）。壁垒必须落到本题的具体机制上；如果调研结论是"该产品没有真壁垒"，那就如实写"无壁垒"并给出证据——这比硬凑三条护城河有价值得多。

### 3.4 `opportunity_map`（行业 / 赛道扫描）

- **适用场景**：调研主体是行业或赛道（AI Agent 赛道、跨境电商 SaaS），读者要判断机会在哪
- **认知路径阶段**：格局（玩家分布、产业链位置）→ 驱动力（什么底层力量在改变格局）→ 裂缝（格局中未被满足的缺口）→ 落点（裂缝中哪个位置适合读者）
- **关键张力**：区分"真机会"和"拥挤的共识"——所有人都看见的裂缝不是裂缝
- **反模板警告**：禁止把行业报告惯用的"市场规模→增速→驱动因素→竞争格局"咨询腔平移进来。如果"裂缝"章节里列的缺口在谷歌第一页都能找到三篇分析，那不是裂缝而是共识——回到 step_6 的假设账本重新找非共识判断（参 25-洞察账本协议的 contrarian 要求）。

### 3.5 `user_voice`（用户研究 / 原声）

- **适用场景**：调研主体是用户/人群的真实声音（求职者的真实面试经历、用户对某产品的真实吐槽）
- **认知路径阶段**：声纹（原声标本，未经修饰的原始材料）→ 聚类（声音归并为几种模式）→ 矛盾（原声之间、原声与官方叙事之间的冲突）→ 洞察（矛盾背后的结构性原因）
- **关键张力**：原声与官方叙事的对撞——官方说"我们重视用户体验"，原声说"客服三天没回"，洞察生在冲突处
- **反模板警告**：禁止把原声当论据装饰品（结论先定，挑几句原声贴金）。原声必须先于结论出现，聚类必须由原声驱动而非由预设框架驱动；如果"矛盾"章节找不到任何原声与官方叙事的冲突，要么样本量不够，要么聚类时被框架磨平了——如实报告"未发现矛盾"也是有效结论。

### 3.6 `mixed_journey`（混合 / 复杂主体）

- **适用场景**：主体无法归入单一类型（一人公司研究 = 人物故事 + 商业模式 + 行业位置；某开源项目 = 技术 + 社区 + 商业）
- **认知路径阶段**：明线（故事：主体的时间线叙事）+ 暗线（机制：商业模式/技术原理的结构分析）双线交织——故事推进到关键节点时，暗线切入解释"为什么这里能成"
- **关键张力**：故事性和分析性的配重——纯故事是传记，纯分析是报告，mixed_journey 要两者互相供能
- **反模板警告**：禁止"前半本讲故事、后半本做分析"的两段式写法——那不叫双线交织，叫两篇文章装订在一起。交织的检验标准是：暗线的每次切入都能指回明线的具体节点；如果暗线章节删掉所有故事引用后仍然成立，说明双线没有真的交织。

---

## 4. 原型可混合

复杂调研允许 **主原型 + 辅原型（≤2 个原型）**：

- 主原型决定报告的整体认知路径形状
- 辅原型必须服务于明确章节，并在 narrative-plan.md 的 `secondary_archetype:` 字段中声明它服务哪些章节（`serves_sections`）
- 禁止无主辅之分的"缝合怪"——如果两个原型都在争整体结构，说明主体拆解不清，回到 task-card.md 重新界定调研主体

示例：技术概念调研 + 决策意图 → `archetype: learning_curve`，`secondary_archetype: decision_forum（serves_sections: §6 选型建议）`。

---

## 5. 底层通用约束（所有原型共用）

v1.x 的元原则保留并精简为三条，作为所有原型的底层约束：

1. **已知→桥梁→未知**：任何原型、任何核心章节，都必须从读者已知的事物切入（与 08 的 H3 对齐）
2. **认知依赖前置**：讲"为什么存在/为什么成立"之前，读者必须已经知道"是什么"；第一性原理位置由本规划声明，不得早于对象介绍（与 22-第一性原理拆解协议对齐）
3. **决策型出口前置**：报告开头必须有一句话结论（与 08 的 H8 对齐），证据与审计材料后置为附录

## 6. 产物文件

产物：`05-analysis/narrative-plan.md`

格式：

```markdown
# 行文思路规划

archetype: learning_curve
why_not: 排除 decision_forum——读者意图是"搞懂这个概念"而非"要不要采用"，决策论坛会迫使报告过早下结论
secondary_archetype: decision_forum（serves_sections: §6 选型建议）
intent_type: 学习

## 认知路径设计
[基于所选原型，写出本报告具体的认知阶段划分，以及每阶段回答的问题]

## 章节顺序

| 章节 | 标题 | 认知阶段 | 读者认知目标 |
|---|---|---|---|
| §1 | 一句话结论 | 出口前置 | 30 秒内知道核心判断 |
| §2 | ... | ... | ... |

## 洞察落点预排
[每条 draft 洞察（insight_ledger.json）预期落在哪个章节]

## 第一性原理位置
- 位置：[§X]
- 理由：[为什么放在这里，必须在对象介绍之后]

## 底层约束检查
- [x] 已知→桥梁→未知（每个核心章节从已知切入）
- [x] 认知依赖前置（第一性原理在对象介绍之后）
- [x] 决策型出口前置（一句话结论在开头）
```

## 7. 验证规则

### 机械检查（Dumb Tools，供验证器用）

- `narrative-plan.md` 必须存在，字符数 ≥ 500
- 必须含 `archetype:` 字段，值 ∈ {`learning_curve`, `decision_forum`, `product_teardown`, `opportunity_map`, `user_voice`, `mixed_journey`}
- 必须含 `why_not:` 字段且字段值非空
- 若含 `secondary_archetype:` 字段，必须同时声明 `serves_sections`
- 必须含"章节顺序"表格和"第一性原理位置"声明
- 必须含"底层约束检查"section

### 语义检查（审计 Agent，step_9.5）

- 所选原型与调研主体/意图是否匹配（对照选择矩阵）
- why_not 的排除理由是否成立，还是敷衍一句话
- 章节顺序是否体现所选原型的认知路径，而非内容分类堆砌
- 是否违反原型的反模板警告（如 decision_forum 的裁决篇幅超过选项+判据）

## 8. 与其他协议的关系

- **前驱**：step_7（多 Agent 分析）——提供分析产物作为规划输入
- **后继**：step_8（反方审计）——基于行文思路检查报告结构；step_9（最终报告）必须遵循 narrative-plan.md
- **14-研究执行状态机**：本协议对应 step_7.5 与门禁 7；v2.0 门禁 7 的检查词同步更新为本协议第 7 节的机械检查项（替换 v1.5 的"认知类型/三级节点"检查词）
- **22-第一性原理拆解协议**：第一性原理位置由本规划声明，必须在对象介绍之后
- **25-洞察账本协议**：narrative-plan.md 须为每条 draft 洞察预排落点章节；原型的"关键张力"通常由 contrarian 洞察承担
- **08-最终报告**：08 的硬约束（H1-H12）是本规划的执行端；本协议负责"结构对不对"，08 负责"底线守没守"
- **09-HTML 美学规范**：呈现层的色彩节奏、结构化块配额由 09 负责，本协议不管

## 9. 防止"自己出题自己改答案"

行文思路规划由调研 Agent 产出，由后续独立角色验证：

1. **step_9.5 独立审计**：审计 Agent 检查原型选择是否匹配、章节递进是否符合原型认知路径
2. **step_10 读者模拟**：读者模拟检查"按此行文思路，目标读者能否逐阶建立认知"；v2.0 支持双读者模拟（领域外行 + 零基础）时，learning_curve 原型的报告必须通过零基础读者的复述测试
3. **审计标准**：原型匹配度、why_not 有效性、认知路径递进、反模板警告合规
