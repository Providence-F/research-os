# 行文思路规划协议（v1.4 新增）

> v1.4 核心新增。解决"报告沦为模板填空，缺乏认知递进"的系统性问题。
> 此步骤在分析（step_7）之后、反方审计（step_8）之前执行，产出 narrative-plan.md。
> 最终报告（step_9）必须遵循此规划，而非 templates/08 的固定顺序。

---

## 1. 为什么需要这一步

v1.3 的问题是：系统规定了"写什么内容"（章节清单 + 字段要求），但没规定"读者应该如何建立认知"（章节之间的递进关系）。

结果：
- 章节按"内容分类"组织（产品→技术→团队→岗位），不是按"认知递进"组织
- 第一性原理被放在对象介绍之前（§2.5），读者还不认识对象就被抛入抽象推理
- 同一套模板用于所有主题，无法适配不同调研对象的认知特点

v1.4 的解决思路：
1. **新增规划步骤**：在写报告前，先规划这份报告的行文思路
2. **固定元原则，放开具体结构**：认知规律不变（元原则），但章节结构由 Agent 动态决定
3. **三级节点提纲法**：借鉴 Kimi 深度研究，按"对象本质→运作机制→决策约束"组织认知递进

---

## 2. 三级节点提纲法（适配版）

借鉴 Kimi 深度研究的三级节点结构（共识→分歧→边界），适配为求职/产品调研导向：

| 层级 | Kimi 原版 | 适配版 | 读者认知阶段 | 回答的问题 |
|---|---|---|---|---|
| **顶层** | 共识性判断 | **对象本质** | 建立基础认知 | 这是什么？解决什么问题？ |
| **中层** | 路径分歧 | **运作机制** | 深化理解 | 怎么做到的？靠什么支撑？ |
| **底层** | 适用边界 | **决策约束** | 指导行动 | 什么情况适用什么判断？风险在哪？ |

**核心原则**：从具象到抽象，从"是什么"到"为什么"到"怎么办"。

---

## 3. 行文思路的元原则（不变的）

这些原则适用于所有报告，不因主题变化而失效：

1. **从具象到抽象**：先让读者认识对象，再讲本质原理
2. **从"是什么"到"为什么"到"怎么办"**：认知三阶段递进
3. **读者认知依赖前置**：讲"为什么存在"前，读者必须已知"是什么"
4. **第一性原理位置动态决定**：在读者建立基础认知后，再讲抽象本质
5. **决策型出口前置**：一句话结论给决策型读者快速出口
6. **证据后置为附录**：正文服务读者理解，证据/审计/来源后置

---

## 4. 执行流程

### 步骤 1：判断报告认知类型

Agent 基于任务卡和 intent_doc.json，判断这份报告属于哪种认知模式：

| 认知类型 | 读者需求 | 行文思路 | 典型场景 |
|---|---|---|---|
| **学习型** | 完整理解对象 | 认知阶梯：是什么→为什么→怎么办 | 求职调研、产品深度拆解 |
| **决策型** | 快速决策 | 金字塔结构：结论→论据→行动 | 一页判断、投资决策 |
| **混合型** | 两者兼有 | 结论前置 + 主体走认知阶梯 | 默认模式 |

判断依据：
- 读者画像（intent_doc.json 的 reader_model）
- 调研类型（task-card.md 的调研类型）
- 深度档位（R0/R1 倾向决策型，R2/R3 倾向学习型或混合型）

### 步骤 2：设计三级节点结构

Agent 基于报告对象的特点，设计三级节点：

**顶层：对象本质**
- 这是什么（1-2句话定义）
- 解决什么问题
- 和读者有什么关系

**中层：运作机制**（3-5个关键机制）
- 产品怎么工作
- 技术怎么实现
- 谁在做、为什么能做
- 和其他方案比有什么不同

**底层：决策约束**（2-3个关键约束）
- 什么情况适用什么判断
- 风险和盲区在哪
- 读者应该怎么做

### 步骤 3：决定章节顺序

Agent 基于认知类型和三级节点，决定章节的递进逻辑。

**混合型默认结构**（Agent 可调整）：

```
阶段1：建立认知（是什么）
  §1 一句话结论（决策型读者的快速出口）
  §2 调研对象到底是什么（先具象，建立基础概念）

阶段2：深化理解（怎么运作）
  §3 核心机制（产品怎么工作、技术怎么实现）
  §4 公司与团队（谁在做、为什么能做）
  §5 差异化与竞争位置（和其他方案比有什么不同）

阶段3：本质洞察（为什么）
  §6 第一性原理（在读者已有具象认知后，再讲抽象本质）

阶段4：决策支持（怎么办）
  §7 风险、盲区与反方观点
  §8 决策建议与行动方案
```

**关键变化**：第一性原理从 §2.5（对象介绍前）移到 §6（对象+机制+竞争之后）。

### 步骤 4：确定第一性原理位置

第一性原理的位置不是固定的，而是由 Agent 基于认知类型动态决定：

- **学习型/混合型**：放在"本质洞察"阶段（读者建立基础认知后）
- **决策型**：可以放在结论之后作为支撑论据，或后置为附录

### 步骤 5：产出 narrative-plan.md

## 5. 产物文件

产物：`05-analysis/narrative-plan.md`

格式：

```markdown
# 行文思路规划

## 报告认知类型
- 类型：[学习型/决策型/混合型]
- 判断依据：[基于什么判断]

## 三级节点结构

### 顶层：对象本质
- 核心定义：[1-2句话]
- 解决的问题：[一句话]
- 与读者的关系：[一句话]

### 中层：运作机制
1. [机制1名称]：[一句话概述]
2. [机制2名称]：[一句话概述]
3. [机制3名称]：[一句话概述]
（3-5个关键机制）

### 底层：决策约束
1. [约束1]：[一句话]
2. [约束2]：[一句话]
（2-3个关键约束）

## 章节顺序

| 章节 | 标题 | 认知阶段 | 读者认知目标 |
|---|---|---|---|
| §1 | 一句话结论 | 建立认知 | 30秒内知道核心判断 |
| §2 | 调研对象到底是什么 | 建立认知 | 知道对象是什么、解决什么问题 |
| ... | ... | ... | ... |

## 第一性原理位置
- 位置：[§X]
- 理由：[为什么放在这里]

## 元原则检查
- [x] 从具象到抽象
- [x] 从"是什么"到"为什么"到"怎么办"
- [x] 读者认知依赖前置
- [x] 第一性原理在基础认知之后
- [x] 决策型出口前置
- [x] 证据后置为附录
```

## 6. 验证规则

### 机械检查（Dumb Tools）
- `narrative-plan.md` 必须存在
- 字符数 ≥ 500
- 必须包含关键词："认知类型"、"三级节点"、"章节顺序"、"第一性原理位置"
- 必须包含"元原则检查"section

### 语义检查（审计 Agent）
- 章节顺序是否符合认知递进（不是内容分类）
- 第一性原理位置是否在对象介绍之后
- 三级节点是否覆盖了报告核心内容
- 章节认知目标是否明确

## 7. 与其他协议的关系

- **前驱**：step_7（多 Agent 分析）——提供分析产物作为规划输入
- **后继**：step_8（反方审计）——反方审计基于行文思路检查报告
- **step_9（最终报告）**：必须遵循 narrative-plan.md，而非 templates/08 固定顺序
- **templates/08**：从"必须遵循的模板"降级为"参考结构"
- **templates/22（第一性原理）**：第一性原理位置由本协议动态决定，不再固定在 §2.5

---

## 8. 与 templates/08 的关系变化

v1.3：templates/08 是"必须遵循的模板"，章节顺序固定
v1.4：templates/08 降级为"参考结构"，行文思路由 narrative-plan.md 动态决定

templates/08 仍然提供：
- 写作约束（术语处理、表格使用、色彩节奏）
- 必须包含的内容元素（一句话结论、第一性原理、来源表等）
- 美学规范参考

templates/08 不再规定：
- 章节的具体顺序（由 narrative-plan.md 决定）
- 第一性原理的固定位置（由 narrative-plan.md 决定）

---

## 9. 防止"自己出题自己改答案"

行文思路规划由调研 Agent 产出，由后续独立审计 Agent 验证：

1. **step_9.5 独立审计**扩展：审计 Agent 不仅检查报告内容，还检查行文思路是否合理
2. **step_10 读者模拟**扩展：读者模拟检查"按此行文思路，读者能否建立认知"
3. **审计标准**：行文思路是否符合元原则、章节递进是否合理、第一性原理位置是否正确
