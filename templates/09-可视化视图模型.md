# 可视化视图模型模板

> `final-report.md` 负责完整论证，`view-model.json` 负责 HTML 怎么被读者快速理解。不要把正文复制进视图模型，只抽出可视化所需的数据结构。

## 1. 基本原则

- HTML 必须仍然保留完整正文。
- 第一屏必须先降低认知负担：判定、摘要卡片、关键对象、策略或对比。
- R2/R3 且非 `narrative_report` 的项目必须生成 `07-output/view-model.json`。
- 视图模型只存结构化展示数据，不替代证据矩阵和最终报告。

## 3. 按研究模式填写

### thinking_decision / career_strategy

必须有：

- `hero.verdict`：当前判断。
- `summary_cards`：3-6 张关键结论卡。
- `object_cards`：候选项、导师、项目、路径。
- `strategy_tabs`：首选 / 备选 / 保底 / 禁区。
- `comparison_matrix`：横向比较成本、收益、风险、可执行性。

### product_teardown

必须有：

- 产品机制卡片。
- 用户路径或核心 workflow。
- 风险 / 待验证卡片。
- 和竞品或替代方案的比较矩阵。

### opportunity_map

必须有：

- 排名卡片或对象卡片。
- 筛选表格。
- 详情弹窗字段：基础事实、匹配理由、风险、下一步动作、来源。

### user_voice

必须有：

- 用户原声主题卡片。
- 高频需求 / 痛点 / 场景筛选。
- 证据等级和代表性限制。

## 4. 验收

- 第一屏能看懂结论，不需要先滚完整正文。
- 对象拆解不能只藏在长段落里。
- 至少出现一种交互：卡片、Tab、筛选、弹窗、矩阵。
- 附录和审计默认折叠。
