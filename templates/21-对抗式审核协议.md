# 步骤 9.6：对抗式 Subagent 审核（v1.3 新增）

> v1.3 新增强制门禁。在独立审计（9.5）通过后、读者模拟（10）前执行。
> 没有此步骤的产物，不能进入步骤 10。
> 设计原理：对抗比评判容易——subagent 不需要比主 Agent 更聪明，只需要能打破它的论点。

---

## 1. 为什么需要这一步

独立审计（9.5）存在根本性局限：审计 Agent 可能和主 Agent 是同一个，自己审自己等于没人审。

对抗式审核用"攻击"替代"评判"：
- **评判质量**需要全面理解、综合评估 → 难，且容易糊弄
- **尝试打破**只需要找到一个反例、一个可再分的点 → 容易，且难以糊弄

这就像学术论文的同行评审——审稿人不需要比作者更聪明，只需要能找到论文的漏洞。

---

## 2. 执行流程

### 步骤 1：启动 subagent

主 Agent 完成报告后，启动一个 subagent 执行对抗审核。

**subagent 的 context 隔离要求**：
- subagent 只收到 `final-report.md` 的内容
- subagent **不收到**过程文件（证据矩阵、分析文件、反方审计等）
- 这防止 subagent 被过程"合理化"，保持新鲜视角

### 步骤 2：subagent 执行攻击

subagent 的任务是**攻击**，不是**评判**。具体攻击 3 类目标：

**攻击 1：最弱的 3 个论点**
- 找出报告中证据最薄弱的 3 个论点
- 对每个论点给出反例或攻击路径
- 如果论点无法被攻击，说明该论点足够强

**攻击 2：第一性原理"再分"测试**
- 找出报告中的"第一性原理"章节（如有）
- 对每条"不可再分"的原理，尝试"再分"
- 如果能再分，说明不是真第一性原理

**攻击 3：数据罗列检测**
- 检查报告是否有"数据前未解释为什么"的段落
- 标记出"纯数据罗列"的章节

### 步骤 3：主 Agent 回应

主 Agent 必须对 subagent 的每个攻击做出回应：
- **修改报告**：承认攻击有效，修改对应内容
- **反驳攻击**：给出证据反驳 subagent 的攻击
- 不能无视任何攻击

### 步骤 4：写入产物文件

产物：`06-review/adversarial_review.json`

格式：

```json
{
  "schema_version": "research-os-adversarial-v1.0",
  "project_name": "项目名",
  "created_at": "2026-07-12",
  "subagent_context": "isolated (final-report only)",
  "attacks": [
    {
      "id": "A1",
      "type": "weak_argument | first_principles | data_listing",
      "target": "被攻击的论点/原理/段落",
      "attack_content": "攻击内容",
      "attack_strength": "strong | medium | weak"
    }
  ],
  "responses": [
    {
      "attack_id": "A1",
      "response_type": "modify | refute",
      "response_content": "回应内容",
      "modified_section": "如修改，修改了哪个章节"
    }
  ],
  "verdict": {
    "attacks_made": 3,
    "attacks_accepted": 1,
    "attacks_refuted": 2,
    "report_modified": true,
    "overall_assessment": "报告经对抗审核后已强化"
  }
}
```

---

## 3. 验证规则

- 产物文件必须存在：`06-review/adversarial_review.json`
- `attacks` 必须有 ≥3 个攻击
- `responses` 必须对每个 attack 有对应 response
- `verdict.attacks_made` ≥ 3
- 每个 attack 必须有 `id`/`type`/`target`/`attack_content`/`attack_strength`
- 每个 response 必须有 `attack_id`/`response_type`/`response_content`

---

## 4. 为什么这比自审有效

| 维度 | Agent 自审 | 对抗式 subagent |
|---|---|---|
| 动机偏差 | Agent 投资"通过"，倾向自审宽松 | subagent 不投资"通过"，无动机偏差 |
| Context 污染 | Agent 看过所有过程文件，被"合理化" | subagent 只看报告，视角新鲜 |
| 任务清晰度 | "审计质量"是模糊任务 | "找 3 个弱点并攻击"是清晰任务 |
| 难度 | 评判质量需要全面理解 | 尝试打破只需要找一个漏洞 |

---

## 5. 与其他步骤的关系

- 前驱：步骤 9.5（独立审计）
- 后继：步骤 10（读者模拟）
- 没有此产物，步骤 10 不能开始
- 此步骤不替代独立审计，而是补充——独立审计检查"完整性"，对抗审核检查"坚固性"

---

## 6. 成本

- 1 次 subagent 调用
- 不需要用户参与
- 对 15+ 轮的研究项目，约 5-7% 成本增加
