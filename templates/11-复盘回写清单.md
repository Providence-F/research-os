# 复盘回写清单

> 复盘只有写回 router、template、builder、validator 或 scaffold，才算系统进化。只写一篇“经验总结”不算优化。

## 1. 复盘先分类

| 问题类型 | 判断问题 | 必须回写到哪里 |
|---|---|---|
| 任务理解错 | 是不是 research_mode 路由错了？ | `research_router.py` / `10-主题路由规则.md` |
| 证据错 | 是来源等级、独立性、淘汰规则没管住？ | 证据模板 / validator |
| 分析浅 | 是报告模板没要求元问题、机会成本、反方？ | 最终报告模板 / 反方审计模板 |
| 交付形态错 | 是 HTML 不适合这个主题？ | `09-可视化视图模型.md` / builder |
| 验证没抓住 | 是 validator 放过了低质量产物？ | `validate_research_project.py` |
| 脚手架缺文件 | 是新项目没生成必要文件？ | `create_research_project.py` |
| 只是本次内容问题 | 是执行没填好，不是系统缺陷？ | 项目文件，不进入系统模板 |

## 2. 每次复盘必须回答

1. 这次失败主要是路由、研究模块、视图模块、验证器，还是执行内容问题？
2. 是否出现了新的 `research_mode`？
3. 是否需要新的 `view_type` 或 `visual_modules`？
4. 是否有 validator 应该拦住但没拦住的问题？
5. 是否有 scaffold 应该生成但没生成的文件？
6. 哪些经验只属于本项目，不能污染通用模板？

## 3. 回写完成定义

必须至少满足一项：

- 修改 `research_router.py` 或 `10-主题路由规则.md`。
- 修改模板库中的基础模板或模块模板。
- 修改 `build_research_html.py`。
- 修改 `validate_research_project.py`。
- 修改 `create_research_project.py`。
- 明确说明这次只是项目内容问题，不进入系统。

## 4. 禁止伪优化

- 只写复盘文档，不改系统。
- 只在报告里道歉，不升级 validator。
- 用“下次注意”替代脚手架或模板约束。
- 为一个主题复制整套模板，导致模板爆炸。
