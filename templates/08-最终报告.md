> v1.x 的 08 把写作建议与强制规则混杂，硬规则被当建议忽略。v2.0 起本文件只负责必须遵守的底线：H1-H12 全部机械可验证，篇幅 ≤ v1.5 原文件 40%。章节顺序由 step_7.5 的 narrative-plan.md 决定。

## 第一层：硬约束清单（H1-H12）

违反任一 = step_14 验证 FAIL，退回 step_10.5 重写。

| # | 硬约束 | 机械检查 |
|---|---|---|
| H1 | 术语首现解释：术语首次出现格式 `术语（英文，含义）：白话` 或脚注 | 核心术语清单（narrative-plan.md）每术语首现段匹配 `术语（.*）：` 或有脚注 |
| H2 | 类比覆盖率：核心技术概念 ≥80% 有"像什么"类比 | 概念段命中类比词（像/如同/相当于/类似/好比）比例 ≥0.8 |
| H3 | 已知→桥梁→未知：核心章节开头从读者已知事物切入 | 每个核心章节首段命中锚点词（你/我们/日常/熟悉/想象/比如） |
| H4 | 图表义务：表格/图表后跟"这张图告诉读者什么" | 表格/图片块后 200 字符内有非空说明段 |
| H5 | 表格禁区：层级/时间/因果不用表格（用列表/流程） | 标题含 架构/层级/流程/时间线/因果 的章节表格数 = 0 |
| H6 | 洞察落点：verified 洞察在报告中有落点章节 | 每条 verified 的 report_anchor 匹配报告章节标题（联动 25 号 R4.5） |
| H7 | 禁止正确的废话：不可证伪陈述不作段落结论 | 结论句不命中空话词表（非常重要/意义深远/未来可期等）；语义复核归 step_9.6/step_10 |
| H8 | 一句话结论：开头有 hero-verdict 式总判断 | 开头 500 字符内有 `> ` 引用块或"一句话结论"标题 |
| H9 | 读者适配声明：开头声明目标读者与前置知识 | 开头有含"目标读者"和"前置知识"的字段行 |
| H10 | 局限章节：有"没解决什么/证据边界"章节 | 有标题含 局限/边界/没解决/未解决 的章节 |
| H11 | inline code 禁令：正文禁止反引号包术语 | 代码块外反引号计数 = 0 |
| H12 | 来源后置：正文不用内部编号，来源列于文末 | 正文无 `E\d{3}`/`S\d{3}`；文末有"信息来源"章节 |
