## 决策问题

> 调研不是为了"知道更多"，是为了支持一个决策。先写清楚服务什么决策。

## 任务类型分流

> 先判断任务类型，再决定用什么研究范式。不要把所有问题都做成证据型情报整理。

| 类型 | 适用场景 | 优先问题 | 主要产物 |
|---|---|---|---|
| 证据型情报调研 | 公司、产品、行业、竞品、JD、公开信息核验 | 哪些事实可靠？哪些结论能被证据支撑？ | 证据矩阵、来源审计、读者报告 |
| 思考型决策研究 | 职业选择、毕业论文选题、作品集方向、项目优先级、要不要投入某事 | 这件事本身值不值得做？应该投入多少？ | 元分析、机会成本、策略组合、选项逐个拆解 |
| 混合型研究 | 既有外部事实，又需要个人战略判断 | 哪些事实约束决策？哪些判断来自用户模型？ | 证据后置 + 决策分析前置 |

如果任务属于“思考型决策研究”或“混合型研究”，必须先完成下面的深度判断，再进入来源搜集和排序推荐。

## 思考型决策任务必答

1. **元问题**：用户问的是不是正确问题？有没有可能应该先问“要不要做 / 做到什么程度”？
2. **投入策略**：做深、做浅、不做、最低成本完成，分别意味着什么？
3. **机会成本**：这件事会挤占哪些更高杠杆任务？时间、精力、窗口期分别损失什么？
4. **真实收益**：对就业、作品集、学业、长期战略的边际收益分别是什么？哪些收益只是自我叙事？
5. **用户模型**：至少列出 5 个影响决策的个人变量，不能只用 1-2 个标签概括用户。
6. **约束地图**：制度、时间、资源、评价标准、外部协作、执行难度分别有什么硬约束？
7. **选项逐个拆解**：每个候选项都要拆最小可行版本、升级版本、成本、风险、收益、不适合情况。
8. **反向假设**：如果最优策略是“不认真做 / 不做 / 只做合规”，报告敢不敢说？

## SSR / 登录墙 / 不可读页面处理预案

> 官网、SaaS 产品页、招聘平台经常是 SSR、登录墙或验证码。不能因为正文抓不到，就用搜索摘要补成事实。

| 情况 | 处理方式 | 证据等级 |
|---|---|---|
| curl 只能拿到 meta / ld+json，正文不可读 | 标记为 `SSR 不可读`；必要时用 Playwright 抓页面；未抓到正文前只能引用 meta | A（meta 本身）/ E（正文事实） |
| 搜索摘要提到客户/价格/功能，但原文不可访问 | 写入 candidates 或待验证项，不进核心结论 | C/E |
| 登录墙 / 验证码页面 | 不绕过；记录不可访问原因；找公开替代源 | E |
| 第三方汇总无原始 URL | 标 C 级；不能当多源 | C |

## 停止条件

> 证据不足时降级，不继续堆叙事。信息稀缺时收敛深度，不强行写"完整商业分析"。

- [ ] 候选源达到 N 条后停止广撒网
- [ ] 关键事实已有 2 个独立来源支撑
- [ ] 继续搜索只能增加背景知识，不能改变结论
- [ ] 反方审计未导致任何降级 → 审计不够用力，重做
- [ ] 读者版最终报告已经能独立阅读，不需要读者自己打开 5 个过程文件拼答案

## 证据标准

| 等级 | 定义 | 可支持的结论 | 禁止事项 |
|---|---|---|---|
| A | 官方 / 原文 / 完整可核验 | 可以作为核心事实 | 不需要推断补全 |
| B | ≥2 个独立原始来源一致，或可信权威材料 | 可以支持中等强度判断 | 不写成绝对事实 |
| C | 单源 / 摘要 / 列表 / 搜索汇总 / 来源独立性未知 | 只能作为线索 | 不能逐句拆解，不能支撑强结论 |
| D | 合理推断 | 只能标注为推断 | 不能伪装成事实 |
| E | 待验证 | 进入待验证清单 | 不进入结论主体 |
| F | 误匹配 / 不可用 | 剔除 | 不再引用 |

## 验收标准

### 思考深度验收

> 适用于 `topic / portfolio / mixed`，以及所有职业、选题、作品集、项目取舍类任务。

- [ ] 报告前 30% 已回答元问题，而不是直接进入推荐排序
- [ ] 明确写出做深 / 做浅 / 不做 / 最低成本完成的取舍
- [ ] 有机会成本分析，且说清楚会挤占哪些更高优先级任务
- [ ] 有就业 / 作品集 / 学业 / 长期战略的分项收益判断
- [ ] 用户模型包含至少 5 个真实约束或偏好，不把用户压缩成 1-2 个标签
- [ ] 有约束地图：制度、时间、资源、评价标准、协作、执行风险
- [ ] 候选项逐个拆解，不只做第一梯队 / 第二梯队分组
- [ ] 反方审计攻击过“问题是否问错了”和“是否值得投入”
- [ ] 如果最优策略是控制成本或不认真做，最终报告必须直接写出来

### 可信度验收

- [ ] 关键事实可追溯来源（evidence_id）
- [ ] MiMo / 搜索汇总默认 C 级，除非有 ≥2 个独立原始 URL
- [ ] 来源独立性已标注（独立 / 同源传抄 / 未知）
- [ ] 推断已标注为推断
- [ ] 待验证项没有写入结论主体
- [ ] discarded.md 记录了被丢弃的来源及原因
- [ ] 冲突信息进入 conflicts.md，未被"取平均"抹平
- [ ] SSR / 登录墙 / 不可读页面已标注处理方式
- [ ] 反方审计有实质降级（不是装饰）
- [ ] 最终结论有置信度

### 读者交付验收

- [ ] `07-output/final-report.md` 可以独立阅读，不依赖读者打开证据矩阵才能理解结论
- [ ] 实质内容前置：结论、发现、对象解释、机制、场景、差异化、风险、行动建议
- [ ] evidence_id、结论溯源、审计、来源清单后置为附录
- [ ] `08-html/index.html` 从读者版 final-report.md 生成，不是过程文件拼贴
- [ ] HTML 黑白极简、无 emoji、无外部 CDN
- [ ] HTML 有目录跳转、章节锚点、折叠审计或附录交互
- [ ] research_state.json 状态已更新到 drafting/published
