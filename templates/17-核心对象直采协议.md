# 步骤 6.5：核心对象直采协议

> v0.6 新增强制步骤。在步骤 7（多 Agent 分析）之前必须完成。
> 没有此步骤的产物，整个项目不能进入报告写作阶段。

---

## 1. 为什么需要这一步

深度调研的核心是"读者拿到报告后能独立验证每一条判断"。

子代理摘要只是信息起点，不是信息终点。子代理返回"有哪些产品/公司/竞品"，但每个对象的深度信息必须靠 WebFetch 官网直采。

如果跳过这一步，会出现：
- 核心产品只提名字不拆解
- 关键信息来自子代理摘要失真
- 读者无法验证关键判断

---

## 2. 执行流程

### 步骤 1：核心对象识别

调研 Agent 基于子代理广度扫描的结果，识别"必须深拆"的核心对象。

识别标准：
- 官方主推的产品
- ARR 贡献大的产品
- 战略叙事核心的产品
- 技术品牌载体的产品

### 步骤 2：每个核心对象 WebFetch 官网

对每个核心对象，必须：
- WebFetch 官网首页
- WebFetch 产品页（如有）
- WebFetch 定价页（如有）
- 搜索 2-3 篇权威报道

### 步骤 3：提取关键信息

对每个核心对象，提取：
- 产品定位
- 功能矩阵（功能模块级）
- 技术架构
- 定价体系
- 客户案例
- 运营指标

### 步骤 4：写入产物文件

产物：`04-captures/core_objects_fetch_log.md`

格式：

```markdown
# 核心对象直采记录

## 对象 1：[产品名]

### 采集来源
- 官网：https://...
- 定价页：https://...
- 报道：https://...

### 提取的关键信息
- 产品定位：
- 功能矩阵：
  - 模块 1：
  - 模块 2：
- 技术架构：
- 定价：
- 客户案例：
- 运营指标：

### 验证状态
- [x] WebFetch 官网完成
- [x] 关键信息提取到功能模块级
- [x] 多源验证（≥2 个独立来源）

---

## 对象 2：[产品名]
...
```

---

## 3. 验证规则

- 产物文件必须存在：`04-captures/core_objects_fetch_log.md`
- 每个核心对象必须有 URL + 提取的关键信息
- 关键信息必须到功能模块级（不是概述级）
- 验证脚本检查此文件存在 + 内容长度 > 200 字符

---

## 4. 与其他步骤的关系

- 前驱：步骤 6（假设账本）
- 后继：步骤 7（多 Agent 分析）
- 没有此产物，步骤 7 不能开始
- 没有此产物，验证脚本直接 FAIL
