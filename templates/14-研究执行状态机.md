# 14-研究执行状态机

Research OS v0.4 的核心不是多一个 CLI，而是把一次研究从“写报告”改成可检查、可溯源的状态推进。

## 1. 状态顺序

```text
route -> plan -> collect -> evidence -> hypothesize -> red_team -> report -> trace -> view_model -> html -> validate -> done
```

对应文件：

| step | 文件 | 作用 |
|---|---|---|
| route | `research_state.json` | 记录 research_mode / view_type / visual_modules |
| plan | `01-plan/research-execution-plan.md` | 子问题矩阵、初始假设、执行顺序 |
| collect | `02-sources/candidate_pool.json` | 候选来源、对象、淘汰理由 |
| evidence | `03-evidence/evidence_matrix.md` | 可用证据和证据等级 |
| hypothesize | `03-evidence/hypothesis_ledger.json` | 假设如何被支持、反驳、修正、降级 |
| red_team | `06-review/red_team.md` | 反方审计，不允许只做形式审计 |
| report | `07-output/final-report.md` | 面向读者的完整 Markdown 报告 |
| trace | `07-output/trace-manifest.json` | 强结论回链 hypothesis 和 evidence |
| view_model | `07-output/view-model.json` | 面向 HTML 的结构化视图数据 |
| html | `08-html/index.html` | 黑白极简、可交互、保留完整正文的 HTML |

## 2. 下一步动作判定

`research_status.py` 不是简单检查哪个文件缺失，而是先检查研究内核是否成立：

1. 没有 `research_state.json`：先修路由状态。
2. 没有执行计划：先运行 `research_planner.py`。
3. 候选池为空，或没有显式淘汰任何候选：继续做候选池。
4. 假设少于 3 条，或没有任何假设被修正 / 降级 / 拒绝：继续更新假设账本。
5. final-report 已有但 trace-manifest 缺失或为空：先写结论溯源。
6. Validator 有 FAIL：先修验证失败。
7. 研究内核和结论溯源通过后，才补 view-model / HTML。

这个顺序防止系统出现两类错误：

- 候选池和假设账本还没完成，却因为缺 HTML 就提示构建页面；
- 报告写得很顺，但强结论没有回到证据和假设账本。

## 3. Planner 的边界

`research_planner.py` 只生成初始研究计划：

- 子问题矩阵；
- 初始假设；
- 候选池占位；
- 假设账本占位；
- `research_state.json.next_required_action`。

它不替代研究者。真实研究必须继续完成：

- 候选来源召回；
- 显式淘汰；
- 证据矩阵；
- 假设修正；
- 反方审计；
- 读者版报告；
- 结论溯源清单。

## 4. Run Step 的边界

`research_run_step.py` 只自动执行低风险动作：

- `run_research_planner`
- `build_html`

以下动作只输出说明，不自动编造：

- `fill_candidate_pool`
- `fill_evidence_matrix`
- `update_hypothesis_ledger`
- `run_red_team_review`
- `write_reader_first_report`
- `write_trace_manifest`
- `write_view_model`

自动化不能替代判断。

## 5. v0.4 的质量底线

R2/R3 项目至少满足：

- 有 `candidate_pool.json`；
- 候选池不能为空；
- 至少有一个候选被丢弃；
- 被丢弃候选必须写 `discard_reason`；
- 有 `hypothesis_ledger.json`；
- 至少 3 条假设；
- 至少 1 条假设被修正、降级或拒绝；
- 假设必须链接 supporting 或 contradicting evidence；
- 有 `trace-manifest.json`；
- strong claim 必须链接 hypothesis；
- strong claim 必须链接 evidence，或写清 limitations；
- 非 narrative 报告必须有 view model 和视觉模块；
- HTML 必须保留完整正文。
