# 研究执行状态机 v0.7

> v0.7 核心变更：
> - 新增步骤依赖检查（step N done 则依赖项必须 done）
> - 新增前置门禁（6.5 前必须完成 2 和 3）
> - 新增 JSON 字段值非空检查（解决空 JSON 通过问题）
> - 新增 task-card 字段值检查（解决模板说明文字占字符数问题）
> - 新增内容深度指标（URL 数、数据点数、章节数）
> - 新增 HTML 禁止模式检测（滚轮、未闭合 div）
> - 升级写-读-改闭环（结构化重写指令 + 迭代状态追踪）
> - 通用化 HTML 构建器（命令行参数 + 动态可视化识别）
>
> v0.6 保留：
> - 步骤 6.5 核心对象直采（强制门禁）
> - 步骤 9.5 独立审计（强制门禁，5 问全 PASS）
> - 状态-产物绑定（状态由产物推断）
> - 工具回归 Dumb（删除语义判断）
> - 分权制衡（调研 Agent / 审计 Agent / 工具）

## 2. 状态-产物绑定协议（v0.7 强化）

状态不再是 Agent 写的字符串，而是产物的函数。

v0.7 强化点：
1. **字段值非空**（不只是字段名存在）
2. **JSON 字段值非空**（list 字段不能是 []，str 字段不能是空字符串）
3. **内容深度指标**（URL 数、数据点数、章节数）
4. **步骤依赖**（step N done 则依赖项必须 done）

## 3. 强制门禁（v0.7）

### 门禁 1：核心对象直采（步骤 6.5）
- 触发：步骤 7 开始前
- 要求：core_objects_fetch_log.md 存在 + 字符数>=200 + URL>=3 + 对象>=3
- 前置：步骤 2 和 3 必须 done（v0.7 新增）
- 失败后果：不能进入步骤 7

### 门禁 2：独立审计（步骤 9.5）
- 触发：步骤 9 完成后
- 要求：audit_report.md 存在且 5 问全 PASS
- 执行者：独立审计 Agent（不同会话）
- 失败后果：不能进入步骤 10

### 门禁 3：读者模拟（步骤 10）
- 触发：步骤 9.5 通过后
- 要求：reader_diagnosis.json + reader_feedback.md 存在
- 执行者：审计 Agent 扮演读者
- 失败后果：不能进入步骤 10.5

### 门禁 4：写-读-改闭环（步骤 10.5，v0.7 新增）
- 触发：步骤 10 未通过时
- 要求：rewrite_instructions.json 生成 + Agent 执行重写
- 最大迭代：2 轮
- 第 3 轮 fail：让人接手
- 失败后果：不能进入步骤 11

### 门禁 5：HTML 禁止模式（步骤 13，v0.7 新增）
- 触发：HTML 构建后
- 要求：aside.toc 不能含 overflow-y: auto + source-section div 必须正确闭合
- 失败后果：HTML 重构

## 4. 工具回归 Dumb（v0.7 边界）

工具只做：
1. 创建目录
2. 复制模板
3. 写文件
4. 检查文件存在 + 字段完整 + 字段值非空
5. 检查内容深度（URL 数、数据点数、章节数）
6. 检查步骤依赖
7. 检查 HTML 禁止模式
8. Markdown -> HTML 机械转换
9. 动态可视化识别（基于关键词模式匹配）
10. 构建结构化重写指令（不调 LLM）

工具永远不做：
- 路由判断（改为 Agent 显式选择）
- AI 味检测（改为审计 Agent 评估）
- 关键字匹配质量检查（改为审计 Agent 评估）
- hex 字符串美学检查（改为审计 Agent 看截图评估）
- 假设数量检查（改为审计 Agent 判断假设质量）
- 实际重写报告（由 Agent 执行）

## 5. 分权制衡（v0.7）

| 角色 | 职责 | 权力 | v0.7 强化 |
|---|---|---|---|
| 调研 Agent | 生产内容、写产物 | 生产权 | 必须填字段值，不能留空模板 |
| 审计 Agent | 独立审计、读者模拟 | 验证权 | 输出结构化重写指令 |
| 工具 | 记账、检查存在性+字段值+深度+依赖、构建 HTML | 记录权 | 检查更严格，但仍机械 |

调研 Agent 不能自己批改自己的作业。
审计 Agent 必须是独立会话，不知道调研过程。
工具不假装 smart，只做 dumb 的存在性+字段值+深度+依赖检查。

## 7. v0.7 检查项总览

### v0.6 保留检查（7 项）
1. 文件存在性
2. 最小字符数
3. 状态-产物一致性
4. 强制门禁（核心对象直采、独立审计、读者模拟）
5. 来源标注格式
6. HTML 存在性 + reader-first
7. 版本一致性

### v0.7 新增检查（7 项）
1. **JSON 字段值非空**（check_json_field_values）
   - intent_doc.json: initial_intent, discovered_questions, decision_context, reader_profile
   - hypothesis_ledger.json: hypotheses（list 不能为空）
   - candidate_pool.json: items（list 不能为空）
2. **task-card 字段值**（check_task_card_field_values）
   - 调研对象、决策目的、读者画像、核心问题
   - 排除模板说明文字（> 开头的引用块）
3. **步骤依赖**（check_step_dependencies）
   - step 6.5 done -> step 2, 3 必须 done
   - step 7 done -> step 6.5, 5 必须 done
   - step 9 done -> step 7, 8 必须 done
4. **内容深度指标**（check_depth_metrics）
   - final-report.md: URL >= 5, 数据点 >= 10, 章节 >= 5
   - core_objects_fetch_log.md: URL >= 3, 对象 >= 3
5. **HTML 禁止模式**（check_html_forbidden_patterns）
   - aside.toc 不能含 overflow-y: auto
   - source-section div 必须正确闭合
6. **核心对象提及次数**（check_core_object_mentions）
   - 核心对象各至少提及 3 次
7. **前置门禁**（check_prerequisite_gate）
   - step 6.5 done -> step 2, 3 必须 done
