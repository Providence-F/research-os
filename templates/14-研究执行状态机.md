# 研究执行状态机 v2.0

> v2.0 核心变更：
> - 门禁 9 → 12：新增门禁 10（意图树验证）、门禁 11（洞察账本验证）、门禁 12（跨产物一致性）

> Smart Agent. Dumb Tools. 设计哲学、分权制衡。

## 3. 强制门禁（v2.0：12 个门禁）

> 检查方式标注：**机械** = validate_research_project.py 自动执行；**语义** = Agent / 审计 Agent 判断。
> badge 为门禁卡住时看板与状态输出的标识文案。

### 门禁 1：核心对象直采（步骤 6.5 后）— 不变
- 位置：步骤 7 开始前
- 要求：core_objects_fetch_log.md 存在 + 字符数>=200 + URL>=3 + 对象>=3
- 检查方式：机械（验证器）
- 卡住 badge：`BLOCKED@G1 核心对象未直采`
- 失败后果：不能进入步骤 7

### 门禁 2：独立审计（步骤 9.5 后）— 不变
- 位置：步骤 9 完成后
- 要求：audit_report.md 存在且 5 问全 PASS（含行文思路审计）
- 执行者：独立审计 Agent（不同会话）
- 检查方式：机械（5 问结构）+ 语义（审计 Agent 出题）
- 卡住 badge：`BLOCKED@G2 独立审计未通过`
- 失败后果：不能进入步骤 10

### 门禁 3：双读者模拟（步骤 10，v2.0 升级）
- 位置：步骤 9.6 通过后
- 要求：reader_diagnosis.json（v2.0 schema）readers 含 outsider + layman，
  两读者 verdict 皆 pass 且 comprehension_score 达阈值（outsider ≥75、layman ≥65），
  overall_pass 与机械重算结果一致
- 执行者：审计 Agent 扮演两类读者
- 检查方式：机械（schema/阈值/overall_pass 重算）+ 语义（读者模拟本身）
- 卡住 badge：`BLOCKED@G3 双读者未通过（outsider≥75 / layman≥65）`
- 失败后果：不能进入步骤 10.5

### 门禁 4：方向选择（步骤 1.5，v2.0 升级）
- 位置：意图树验证（门禁 10）通过后，任务卡创建前
- 要求：direction_selection.json 存在 + ≥2 边界问题 + 用户回答 + status=direction_confirmed
  + **每个边界问题含 targets_path_id，指向 intent_doc.v07.candidate_paths 中存在的 path_id**
- 检查方式：机械（targets_path_id 引用完整性）+ 语义（用户回答）
- 适用：R2/R3 强制，R0/R1 可选
- 卡住 badge：`BLOCKED@G4 边界问题未挂意图树路径`
- 失败后果：不能创建任务卡

### 门禁 5：对抗式审核（步骤 9.6，v2.0 升级）
- 位置：独立审计通过后
- 要求：adversarial_review.json 存在 + ≥3 攻击 + 每个攻击有回应 + 含 first_principles 类型攻击
  + **必须逐条核验 verified 洞察的 novelty_check**（含 type=insight_novelty 攻击，
  被判定为公开共识的洞察降级为 downgraded）
- 执行者：subagent（context 隔离，只看 final-report + insight_ledger）
- 检查方式：机械（攻击数/字段/insight_novelty 存在性）+ 语义（novelty 判定）
- 卡住 badge：`BLOCKED@G5 对抗审核未过（含洞察 novelty 核验）`
- 失败后果：不能进入双读者模拟

### 门禁 6：第一性原理（贯穿三层）— 不变
- 意图层：intent_doc.json 必须含 first_principles_decomposition（≥3条，每条含principle/irreducibility_argument/evidence_basis）
- 任务层：research-plan.md 必须含"元问题"section（≥200字符）
- 报告层：final-report.md 必须含"第一性原理/本质/为什么/底层逻辑"章节（≥500字符），且在"调研对象"章节之后
- 对抗层：adversarial_review.json 必须含 type=first_principles 的攻击+回应
- 检查方式：机械
- 卡住 badge：`BLOCKED@G6 第一性原理缺失`
- 失败后果：验证器报 FAIL

### 门禁 7：行文思路规划（步骤 7.5，v2.0 升级检查词）
- 位置：步骤 8 开始前
- 要求：
  - narrative-plan.md 存在，字符数 ≥ 500
  - **含 `archetype:` 字段，值 ∈ {learning_curve, decision_forum, product_teardown, opportunity_map, user_voice, mixed_journey}（允许 aux_archetype 辅原型）**
  - **含 `why_not:` 字段且非空（≥10 字符）**
  - 含"章节顺序"表格、"第一性原理位置"声明、"底层约束检查"section
- v2.0 变更：检查词从 v1.5 旧关键词（认知类型/三级节点）替换为 archetype 枚举 + why_not（对齐 23-行文思路规划协议 v2.0 第 7 节）
- 检查方式：机械（枚举/字段非空）+ 语义（原型匹配度归审计 Agent）
- 卡住 badge：`BLOCKED@G7 叙事原型未声明或 why_not 为空`
- 失败后果：不能进入步骤 8（反方审计）

### 门禁 8：写-读-改闭环（步骤 10.5）— 不变
- 位置：步骤 10 未通过时
- 要求：rewrite_instructions.json 生成 + Agent 执行重写
- 最大迭代：2 轮；第 3 轮 fail 让人接手
- 检查方式：机械
- 卡住 badge：`BLOCKED@G8 写-读-改闭环未收敛`
- 失败后果：不能进入步骤 11

### 门禁 9：美学合规验证（步骤 13）— 不变
- 位置：HTML 构建后
- 判定依据：`templates/09-HTML美学规范.md` v0.7 第7节「最小强制CSS基线（不可绕过）」
- 要求：强制基线 CSS / `<head>` Google Fonts（Lora + Inter + JetBrains Mono）/
  `<body>` 结构（.reading-progress + .page-shell + aside.toc sticky + .vm-hero + section.chapter）/
  强制 JS（进度条 + IntersectionObserver）/ 禁止模式 / 14 项美学合规自检清单
- 执行约束：Agent 必须从美学规范 v0.7 第 7 节直接复制片段，不得凭记忆重写
- 检查方式：机械
- 卡住 badge：`BLOCKED@G9 HTML 美学不合规`
- 失败后果：HTML 重构

### 门禁 10：意图树验证（v2.0 新增）
- 位置：意图发现完成后、step_1.5 方向选择前
- 要求（对齐 24-意图拆解协议 finalize 硬校验）：
  - 5 轮 exploration_history 全部有 result
  - intent_tree 非空、含 ≥1 个 L1_meta 节点、≥3 个 L2_mechanism 节点
  - parent_id 引用完整（Q0 为 null，其余指向已存在节点）、无重复 id
  - candidate_paths ≥2 且恰 1 条 selected=true，未选中必有非空 pruned_reason
  - blocks_plan_if_unanswered=true 的澄清问题 ≤3
  - success_criteria 非空
- 检查方式：机械（验证器；仅 status=exploration_complete 时硬校验，骨架状态 WARN）
- 卡住 badge：`BLOCKED@G10 意图树未验证`
- 失败后果：不能进入 step_1.5 方向选择

### 门禁 11：洞察账本验证（v2.0 新增）
- 位置：step_9 报告草稿前（step_8 反方审计后）
- 要求（对齐 25-洞察账本协议 R4）：
  - 05-analysis/insight_ledger.json 存在，insights 非空
  - verified 洞察数达深度阈值：R2 ≥3、R3 ≥5（R0/R1 不强制，WARN）
  - verified+draft 中 ≥1 条 type=contrarian
  - 每条 verified：evidence_ids ≥2 且 report_anchor 非空
  - rejected/downgraded 条目 report_anchor 必须为空字符串
  - step_9 前不允许残留 status=draft 条目（语义流转由红队/对抗审核执行）
- 检查方式：机械（数量/枚举/字段约束）；洞察质量（反共识/可证伪/决策力）归语义层
- 卡住 badge：`BLOCKED@G11 洞察账本不达标（verified 不足或无 contrarian）`
- 失败后果：不能进入 step_9 报告草稿

### 门禁 12：跨产物一致性（v2.0 新增）
- 位置：step_11 溯源清单前后（step_12 视图模型前）
- 要求：
  - intent_tree 中 status=answered 且 priority=must 的节点 answer_pointer 非空
  - answer_pointer 锚点在 final-report.md 中存在（宽松匹配：≥4 字中文片段命中即过，不命中 WARN）
  - verified 洞察的 report_anchor 锚点在 final-report.md 中存在（同上宽松匹配）
  - trace-manifest.json 的 claim → hypothesis → evidence 链路引用的 id 全部存在
    （hypothesis_ids ∈ hypothesis_ledger.json，evidence_ids ∈ evidence_matrix.md）
- 检查方式：机械
- 卡住 badge：`BLOCKED@G12 跨产物引用断裂`
- 失败后果：不能进入步骤 12/13

## 6. 工具回归 Dumb（v2.0 边界）

工具只做：
1. 创建目录
2. 复制模板
3. 写文件
4. 检查文件存在 + 字段完整 + 字段值非空
5. 检查内容深度（URL 数、数据点数、章节数）
6. 检查步骤依赖
7. 检查 HTML 禁止模式 + 必须结构
8. Markdown -> HTML 机械转换
9. 动态可视化识别（基于关键词模式匹配）
10. 构建结构化重写指令（不调 LLM）
11. 检查 narrative-plan.md 存在 + archetype 枚举 + why_not 非空（v2.0 检查词）
12. **v2.0 新增**：意图树结构校验（分层/parent_id/候选路径/澄清上限/success_criteria）
13. **v2.0 新增**：洞察账本机械校验（verified 数量/contrarian 存在性/evidence_ids≥2/report_anchor 空值约束）
14. **v2.0 新增**：双读者诊断结构校验 + overall_pass 机械重算
15. **v2.0 新增**：报告硬约束可机械部分（H1 术语解释覆盖率/H5 表格禁区 WARN/H11 inline code/H12 来源后置）
16. **v2.0 新增**：跨产物引用一致性（answer_pointer/report_anchor 宽松锚点匹配、trace 链路 id 存在性）

工具永远不做：
- 路由判断（改为 Agent 显式选择）
- AI 味检测（改为审计 Agent 评估）
- 关键字匹配质量检查（改为审计 Agent 评估）
- hex 字符串美学检查（改为审计 Agent 看截图评估）
- 假设数量检查（改为审计 Agent 判断假设质量）
- 实际重写报告（由 Agent 执行）
- 行文思路质量判断（由审计 Agent 评估，工具只检查存在性和枚举值）
- **意图树/洞察的语义合理性判断**（树结构对不对、洞察是不是真洞察，归 Agent 与对抗审核）
- **锚点格式强制**（answer_pointer/report_anchor 只宽松匹配，不强制锚点格式）

## 7. 分权制衡（v2.0）

| 角色 | 职责 | 权力 | v2.0 强化 |
|---|---|---|---|
| 调研 Agent | 生产内容、写产物、拆意图树、规划行文思路、登记洞察 | 生产权 | 新增意图树构建 + 洞察登记职责 |
| 审计 Agent | 独立审计、双读者模拟、行文思路审计 | 验证权 | 读者模拟升级为双读者 |
| 对抗 subagent | 攻击第一性原理与洞察 novelty | 对抗权 | 新增 insight_novelty 攻击类型 |
| 工具 | 记账、存在性+字段值+深度+依赖+结构检查、构建 HTML | 记录权 | 新增意图树/洞察账本/双读者/跨产物一致性机械检查 |

调研 Agent 不能自己批改自己的作业。
审计 Agent 必须是独立会话，不知道调研过程。
工具不假装 smart，只做 dumb 的存在性+字段值+深度+依赖+枚举+阈值检查。
