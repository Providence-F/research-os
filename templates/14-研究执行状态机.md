## 3. 强制门禁（v1.4：9 个门禁）

### 门禁 1：核心对象直采（步骤 6.5）
- 触发：步骤 7 开始前
- 要求：core_objects_fetch_log.md 存在 + 字符数>=200 + URL>=3 + 对象>=3
- 前置：步骤 2 和 3 必须 done
- 失败后果：不能进入步骤 7

### 门禁 2：独立审计（步骤 9.5）
- 触发：步骤 9 完成后
- 要求：audit_report.md 存在且 5 问全 PASS
- 执行者：独立审计 Agent（不同会话）
- v1.4 扩展：审计范围增加行文思路检查
- 失败后果：不能进入步骤 10

### 门禁 3：读者模拟（步骤 10）
- 触发：步骤 9.6 通过后
- 要求：reader_diagnosis.json + reader_feedback.md 存在
- 执行者：审计 Agent 扮演读者
- 失败后果：不能进入步骤 10.5

### 门禁 4：方向选择（步骤 1.5）
- 触发：意图识别完成后，任务卡创建前
- 要求：direction_selection.json 存在 + ≥2边界问题 + 用户回答 + status=direction_confirmed
- v1.4 变更：从"≥2方向选择"改为"≥2边界问题"
- 适用：R2/R3 强制，R0/R1 可选
- 失败后果：不能创建任务卡

### 门禁 5：对抗式审核（步骤 9.6）
- 触发：独立审计通过后
- 要求：adversarial_review.json 存在 + ≥3攻击 + 每个攻击有回应 + 含first_principles类型攻击
- 执行者：subagent（context隔离，只看final-report）
- 失败后果：不能进入读者模拟

### 门禁 6：第一性原理（贯穿三层）
- 意图层：intent_doc.json 必须含 first_principles_decomposition（≥3条，每条含principle/irreducibility_argument/evidence_basis）
- 任务层：research-plan.md 必须含"元问题"section（≥200字符）
- 报告层：final-report.md 必须含"第一性原理/本质/为什么/底层逻辑"章节（≥500字符）
- **v1.4 修订**：报告层第一性原理必须在"调研对象到底是什么"章节之后
- **v1.4 新增**：narrative-plan.md 必须声明第一性原理的位置
- 对抗层：adversarial_review.json 必须含 type=first_principles 的攻击+回应
- 失败后果：验证器报 FAIL

### 门禁 7：行文思路规划（步骤 7.5，v1.4 新增）
- 触发：步骤 8 开始前
- 要求：
  - narrative-plan.md 存在
  - 字符数 ≥ 500
  - 必须包含关键词："认知类型"、"三级节点"、"章节顺序"、"第一性原理位置"
  - 必须包含"元原则检查"section
- v1.4 新增门禁
- 失败后果：不能进入步骤 8（反方审计）

### 门禁 8：写-读-改闭环（步骤 10.5）
- 触发：步骤 10 未通过时
- 要求：rewrite_instructions.json 生成 + Agent 执行重写
- 最大迭代：2 轮
- 第 3 轮 fail：让人接手
- 失败后果：不能进入步骤 11

### 门禁 9：美学合规验证（步骤 13，v1.4 强化）
- 触发：HTML 构建后
- 判定依据：`templates/09-HTML美学规范.md` v0.7 第7节「最小强制CSS基线（不可绕过）」
- 要求：
  - **强制基线**：HTML `<style>` 必须包含美学规范v0.7第7.1节的CSS片段（不可手写替代、不可简化、不可用其他值替换）
  - **强制 `<head>`**：必须加载Google Fonts CDN（Lora + Inter + JetBrains Mono）
  - **强制 `<body>` 结构**：必须包含 `.reading-progress` + `.page-shell` grid布局 + `<aside class="toc">` sticky + `.vm-hero` + `<section class="chapter">`
  - **强制 JavaScript**：必须包含scroll进度条更新 + IntersectionObserver TOC高亮
  - **禁止模式**：无 overflow-y:auto 在 aside.toc + source-section div 正确闭合
  - **必须结构**：14 项美学合规自检清单全部通过（参见美学规范v0.7第8节）
    - `.page-shell` 双列布局
    - `<aside class="toc">` 固定侧栏 sticky
    - `.vm-hero` Hero 区
    - `.hero-verdict` 一句话结论（30px）
    - `.hero-summary` 摘要（16px）
    - `.hero-meta` 元信息（13.5px）
    - `.kicker` 小标题（11.5px 全大写 accent 色）
    - `.reading-progress` 阅读进度条
    - `<section class="chapter">` 章节结构 + border-top
    - `Lora` 衬线字体（正文 h1/h2/h3/p）
    - `Inter` 无衬线字体（元信息）
    - `#faf9f5` 米色背景（不是 #ffffff 或 #fafafa）
    - `#b85b44` 暖砖红 accent（不是 #8b5a3c 或 #d97757）
    - 表格 Stripe Press 风格（th 双线底边，无重边框，hover 高亮）
    - `<details>` 折叠区用 `▸` 旋转箭头
  - **执行约束**：Agent 生成HTML时必须从美学规范v0.7第7节直接复制CSS/HTML/JS片段，不得从记忆或推测重写
- 失败后果：HTML 重构（必须重新从美学规范v0.7第7节复制基线）
- **v1.4 强化原因**（2026-07-18）：AI眼镜深度调研报告HTML完全手写绕过美学规范，导致10项严重违规。原HTML门禁只列9项必须结构，未强制Agent从美学规范读取CSS，未引用最小强制基线，导致Agent可以"凭记忆"生成不合规HTML。

## 5. 工具回归 Dumb（v1.4 边界）

工具只做：
1. 创建目录
2. 复制模板
3. 写文件
4. 检查文件存在 + 字段完整 + 字段值非空
5. 检查内容深度（URL 数、数据点数、章节数）
6. 检查步骤依赖
7. 检查 HTML 禁止模式 + 必须结构
8. Markdown -> HTML 机械转换
9. 动态可视化识别（基于关键词模式匹配）
10. 构建结构化重写指令（不调 LLM）
11. **v1.4 新增**：检查 narrative-plan.md 存在 + 关键词 + 元原则检查 section

工具永远不做：
- 路由判断（改为 Agent 显式选择）
- AI 味检测（改为审计 Agent 评估）
- 关键字匹配质量检查（改为审计 Agent 评估）
- hex 字符串美学检查（改为审计 Agent 看截图评估）
- 假设数量检查（改为审计 Agent 判断假设质量）
- 实际重写报告（由 Agent 执行）
- **行文思路质量判断**（由审计 Agent 评估，工具只检查存在性和关键词）

## 6. v1.4.1 变更说明（2026-07-18）

### 变更内容
1. **门禁数量**：8 个门禁 → 9 个门禁
2. **新增门禁 9**：美学合规验证（步骤 13）
3. **强化要求**：HTML 必须从 `templates/09-HTML美学规范.md` v0.7 第7节「最小强制CSS基线（不可绕过）」直接复制 CSS/HTML/JS 片段，不得从记忆或推测重写
4. **自检清单扩展**：9 项必须结构 → 14 项美学合规自检清单

### 变更原因
AI眼镜深度调研报告HTML完全手写绕过美学规范，导致10项严重违规：
- 背景色 `#fafafa`（应为 `#faf9f5`）
- 无 accent 色（用纯黑）
- `-apple-system` 无衬线字体（应为 Lora 衬线）
- 未加载 Google Fonts
- 字号用 em 单位（应为 px）
- 无 reading-progress 进度条
- 无 sticky aside.toc
- 无 .chapter 类
- 表格用全边框+黑底白字 th（应为 Stripe Press 风格）
- 无 .vm-hero

### 根因
1. **直接根因**：HTML 完全手写，绕过了 build_research_html.py 工具
2. **流程根因**：8 个门禁中没有"美学合规验证"门禁
3. **规范本身问题**：美学规范v0.5只有"自检清单"而无"最小强制CSS基线"，Agent可以凭记忆生成不合规HTML

### 预防机制
- 美学规范v0.7新增第7节「最小强制CSS基线（不可绕过）」
- 状态机v1.4.1新增门禁9「美学合规验证」
- Step 13 HTML构建时必须从美学规范v0.7第7节直接复制CSS/HTML/JS片段
