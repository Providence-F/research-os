# Research OS 使用说明 v0.5

> **唯一入口**：Agent 拿到 Research OS 时，必须先读本文档。
> 本文档同步到 Research OS v0.5 的真实状态（不是 v0.1 的旧版）。
> 如果本文档和其他文件冲突，以本文档为准。

---

## 1. Research OS 是什么

Research OS 是一个**深度调研工作流系统**。给定一个研究主题，它会引导你走完"任务定义 → 候选源采集 → 证据矩阵 → 假设账本 → 反方审计 → 最终报告 → HTML 可视化"的完整链路，产出一份有信任度保证的深度报告。

**核心原则**：内部文件服务可信度，最终报告服务读者。

## 4. 强制执行顺序

Agent 必须按以下顺序执行，每步完成后跑 `validate_research_project.py` 检查。

### 步骤 0：脚手架（必做）

```bash
python ros.py new "项目名"
```

**脚本**：`create_research_project.py`
**产物**：完整目录结构 + 全部必产物的空模板
**关键**：v0.5 脚手架会复制**全部 14 个模板**（不是旧的 5 个），并初始化 intent_doc.json / goal_ledger.json / view-model.json / trace-manifest.json / hypothesis_ledger.json / candidate_pool.json。

### 步骤 1：路由（必做）

**脚本**：`research_router.py` + `intent_discovery.py`
**产物**：`01-plan/route_result.json` + `01-plan/intent_doc.json`
**目的**：根据主题判断应该用哪些场景模板（平台审计/用户原声/JD拆解/复盘回写）

### 步骤 2：任务卡（必做，需人工确认）

**模板**：`01-调研任务卡.md`
**产物**：`00-task/task-card.md`
**必须字段**：调研对象 / 类型 / 深度 / 决策目的 / 读者画像 / 子问题 / 验收标准 / 停止条件 / 时间预算 / 输出清单 / 人工确认点
**🛑 人工确认点**：任务卡必须经用户确认才能进入下一步

### 步骤 3：调研方案（必做，需人工确认）

**模板**：`02-调研方案.md`
**产物**：`01-plan/research-plan.md`
**内容**：subagent 分工 / 证据等级定义 / HTML 结构要求 / 反方审计预设
**🛑 人工确认点**：调研方案必须经用户确认才能进入下一步

### 步骤 4：候选源采集

**模板**：`12-候选池.md`
**产物**：`02-sources/candidates.md` + `02-sources/discarded.md`
**关键**：`discarded.md` 是**必产物**——丢弃的源也要记录，写明为什么丢
**证据等级**：A=源码/技术报告，B=官方博客，C=社区评测，D=弱证据

### 步骤 5：证据矩阵

**模板**：`03-证据矩阵.md`
**产物**：`03-evidence/evidence_matrix.md`
**内容**：每条证据编号（E001...）、来源、等级、支持哪个假设

### 步骤 6：假设账本 + 冲突

**模板**：`04-假设账本.md`
**产物**：`03-evidence/hypothesis_ledger.json` + `03-evidence/conflicts.md`
**关键**：假设要可证伪。冲突信息要记录，不能假装没看见

### 步骤 7：多 Agent 分析（R2+）

**产物**：`05-analysis/*.md`
**方式**：subagent 并行采集，每个 subagent 负责一个子问题
**关键**：subagent 产出必须标注证据编号引用

### 步骤 8：反方审计（必做，必须触发至少 1 次降级）

**模板**：`07-反方审计.md`
**产物**：`06-review/red_team.md`
**关键**：至少发起 4 次攻击，至少 1 次降级（结论从 confirmed 降到 partial/rejected）

### 步骤 9：最终报告草稿

**模板**：`08-最终报告.md`
**产物**：`07-output/final-report.md`
**关键**：深度正文为主体（不是卡片）。第一性原理推导。所有术语括号解释。

### 步骤 10：读者模拟 + 报告重写（v0.10 写-读-改闭环）

**脚本**：`reader_simulation.py` → `final_report_writer.py`
**产物**：`07-output/final-report.md`（重写后）
**流程**：
1. `reader_simulation.py` 模拟读者阅读，找出"看不懂/跳跃/缺术语解释"的地方
2. `final_report_writer.py` 根据读者反馈重写报告
3. 可能迭代多轮，直到读者模拟通过

### 步骤 11：溯源清单

**模板**：`15-结论溯源清单.md`
**产物**：`07-output/trace-manifest.json`
**内容**：每条结论 → 支持它的证据编号链

### 步骤 12：视图模型

**模板**：`09-可视化视图模型.md`
**产物**：`07-output/view-model.json`
**schema**：`research-os-view-model-v0.5`
**必含字段**：`visual_modules`（hero/summary_cards/object_cards/strategy_tabs/comparison_matrix/full_report/appendix_fold）

### 步骤 13：HTML 构建

**脚本**：`build_research_html.py`
**产物**：`08-html/index.html`
**美学规范**：必须遵循 `09-HTML美学规范.md`（不是 .py 代码里写死的 CSS）
**关键**：HTML 主体是深度正文（≥ 15000 字），不是只有卡片

### 步骤 14：验证（强制）

**脚本**：`validate_research_project.py`
**检查项**：
- 产物完整性（14 个必产物）
- 最终报告章节齐全
- 证据矩阵字段正确
- 假设账本可证伪
- 反方审计至少 1 次降级
- view-model.json 符合 v0.2 schema
- HTML 美学合规（v0.5 新增）
- 版本号一致性（v0.5 新增）

### 步骤 15：发布

**产物**：`09-publish/` 目录 + 桌面副本
**关键**：HTML 必须复制到桌面，文件名清晰

## 5. 深度档位

| 档位 | 用途 | 产物 |
|---|---|---|
| R0 | 快速问答 | 单段回答 |
| R1 | 标准调研 | task-card + final-report.md |
| R2 | 深度调研 | 全部 14 个必产物 + HTML |
| R3 | 极致深度 | R2 + 多轮读者模拟 + 多轮红队 |

**默认档位**：R2

## 6. CLI 命令

```bash
# 新建项目
python ros.py new "项目名"

# 生成任务卡（交互式）
python ros.py plan

# 查看状态
python ros.py status

# 执行下一步
python ros.py run

# 验证项目
python ros.py validate

# 构建 HTML
python ros.py build

# 意图探索
python ros.py discover

# 目标追踪
python ros.py goal

# 迭代日志
python ros.py iterate

# 报告重写（写-读-改闭环）
python ros.py rewrite

# 确认步骤
python ros.py confirm

# 仪表盘
python ros.py dashboard
```

## 8. 美学规范（HTML 必读）

生成 HTML 前，**必须读** `09-HTML美学规范.md`。

核心要点：
- 背景 `#faf9f5`（米色，不是纯白）
- accent `#b85b44`（暖砖红，不是旧版 `#8b5a3c`）
- 字体 Lora + Inter + JetBrains Mono（Google Fonts CDN）
- h1 = 38px，hero-verdict = 30px，h2 = 26px
- 正文行高 1.75
- 必须有阅读进度条 + 侧栏 TOC
- 深度正文为主体（不是只有卡片）
- 表格用 Stripe Press 风格（无重边框）

## 9. 版本治理规则

1. **当前版本**：v0.5
2. **版本号标记**：每个文件头加 `<!-- ros-version: v0.5 | last-updated: YYYY-MM-DD | status: current -->`
3. **归档**：旧版本文件移到 `archive/v0.x/`，不删除
4. **archive/ 不作为规范**：Agent 不应参考 archive/ 里的文件
5. **CHANGELOG.md**：每次版本更新必须记录变更

## 10. 常见错误（Agent 必看）

### 错误 1：跳过入口文档

❌ 直接读 `09-可视化视图模型.md` 就开始写 HTML
✅ 必须先读 `00-使用说明.md`（本文档），理解完整流程

### 错误 2：用旧版美学

❌ 用 `#faf7f0` 背景、`#8b5a3c` accent、Georgia 字体
✅ 用 `#faf9f5` 背景、`#b85b44` accent、Lora 字体（见 `09-HTML美学规范.md`）

### 错误 3：只有卡片没有正文

❌ HTML 全是 summary_cards / object_cards，没有深度正文
✅ HTML 主体是深度正文（≥ 15000 字），卡片是辅助

### 错误 4：跳过反方审计

❌ 不做 red_team.md，或做了但没有触发降级
✅ 至少 4 次攻击，至少 1 次降级

### 错误 5：discarded.md 缺失

❌ 只有 candidates.md，没有 discarded.md
✅ discarded.md 是必产物——丢弃的源也要记录

### 错误 6：状态机不一致

❌ research_state.json 报告 "step 9 done" 但实际 final-report.md 不存在
✅ 状态必须准确反映实际完成情况

### 错误 7：subagent 写错路径

❌ subagent 把分析文件写到工作目录而不是项目 05-analysis/
✅ subagent 产出必须归位到标准目录结构

## 11. 场景模板路由

根据调研主题，可能需要额外的场景模板：

| 场景 | 模板 | 何时用 |
|---|---|---|
| 平台审计 | 04-平台审计矩阵.md | 调研某个平台/产品时 |
| 用户原声 | 05-用户原声库.md | 需要收集真实用户评价时 |
| JD 拆解 | 06-JD逐句拆解.md | 求职/招聘场景 |
| 复盘回写 | 11-复盘回写清单.md | 项目完成后复盘 |

`research_router.py` 会根据主题自动推荐场景模板。

## 12. 人工确认点

以下步骤必须经用户确认才能继续：

1. **步骤 2**：任务卡确认（task-card.md）
2. **步骤 3**：调研方案确认（research-plan.md）
3. **步骤 13**：HTML 美学合规确认

其他步骤可连续执行，但每步完成后必须跑 validator。

## 13. 升级指南

如果要升级 Research OS 到新版本：
1. 在 `CHANGELOG.md` 记录变更
2. 更新所有文件的 `ros-version` 头
3. 旧文件移到 `archive/v0.x/`
4. 更新本文档（`00-使用说明.md`）
5. 跑 `validate_research_project.py` 确保不破坏现有项目
