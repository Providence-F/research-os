# 意图拆解协议（v2.0 新增）

> v2.0 核心新增。解决"意图识别停在记录层、调研任务规划僵化"的系统性问题。
> 此协议在脚手架（step_0）之后、方向选择（step_1.5）之前执行，产出意图树 intent tree。
> 方向选择（step_1.5）的边界问题必须在意图树已选路径上提出。

---

## 1. 为什么需要这一步

v1.x 的问题：意图发现是三轮模板问答（记录字面→挖差距→固化），产出的是"用户要什么"的记录，而不是"调研该怎么打"的作战地图。

后果：
- 意图树字段存在但从未被验证——形同虚设
- 调研方案直接从 6 个硬编码模板倒出来，和真实意图弱相关
- 方向选择的边界问题凭空提出，不针对意图分叉点
- 澄清门禁可以一口气问 10 个问题，没有上限，用户被审讯

v2.0 的解决思路：
1. **意图即树**：把意图拆解成一棵问题树——根是调研主题，节点是问题，边是依赖，路径是调研策略
2. **规划从树生长**：子问题矩阵必须引用树节点 id，禁止无源问题
3. **边界问题打在分叉上**：step_1.5 的边界问题必须标注它剪的是哪条候选路径
4. **澄清上限**：blocks_plan 的澄清问题 ≤3，超出降级为开放问题

---

## 2. 意图树的结构

意图树是调研的作战地图。每个节点是一个问题，树的分层对应认知的深度：

| 层 | 名称 | 回答什么 | 例子（拆解 Manus） |
|---|---|---|---|
| L0 | 根问题 | 这次调研到底要回答什么 | Manus 的产品机制是什么、值不值得学 |
| L1 | 元问题 | 这个问题问对了吗、该投入多少 | 真问题是"Agent 产品如何做任务编排"，不是"Manus 是不是噱头" |
| L2 | 机制问题 | 对象怎么运作 | 任务如何被拆解、执行、验收 |
| L3 | 证据问题 | 支撑机制判断的事实 | 官方文档怎么说、实测表现如何、用户怎么评价 |
| L4 | 反问题 | 什么证据会推翻当前框架 | 如果 Manus 只是包装，哪些观察能证伪"自研编排" |

### 节点字段（机器可验证）

```json
{
  "id": "Q1.2",
  "layer": "L1_meta",
  "question": "用户问的是不是正确问题？",
  "parent_id": "Q0",
  "status": "open | answered | dropped",
  "answer_pointer": "03-evidence/evidence_matrix.md#sec2 或 final-report.md 章节锚点",
  "depends_on": ["Q2.1"],
  "research_mode": "thinking_decision",
  "priority": "must | should | could"
}
```

硬规则：
- `parent_id` 必须指向已存在的节点（根节点 Q0 的 parent_id 为 null）
- 每个 `status=answered` 的节点必须有 `answer_pointer`
- `depends_on` 形成的是 DAG，禁止环
- must 节点未全部 answered 时，step_9 报告草稿不能标记 done

## 3. 候选路径与剪枝

意图树不只是一棵树，还包含**被放弃的路径**——这保证方向选择是显式的，不是默认的。

```json
{
  "candidate_paths": [
    {
      "path_id": "P1",
      "name": "机制拆解路径",
      "description": "把 Manus 当工程对象拆",
      "expected_yield": "知道它怎么工作、壁垒在哪",
      "cost": "高：需要实测+源码级分析",
      "selected": true
    },
    {
      "path_id": "P2",
      "name": "商业叙事路径",
      "description": "把 Manus 当营销案例拆",
      "expected_yield": "知道它怎么讲故事",
      "cost": "低：公开材料足够",
      "selected": false,
      "pruned_reason": "用户已读过营销分析，边际收益低"
    }
  ]
}
```

硬规则：
- ≥2 条候选路径，每条有 expected_yield 和 cost
- 恰有 1 条 selected=true，其余必须有 pruned_reason
- step_1.5 的每个边界问题必须含 `targets_path_id`，指向它正在剪枝或确认的路径

## 4. 与后续步骤的绑定

| 后续产物 | 绑定规则 | 机械检查 |
|---|---|---|
| direction_selection.json | 边界问题含 targets_path_id | 字段存在+指向存在的 path_id |
| research-plan.md 子问题矩阵 | 每行子问题含树节点 id（如 Q2.1） | 每行能 grep 到 Q\d+ 模式 id |
| hypothesis_ledger.json | 假设可挂到树节点（可选字段 node_id） | 无（语义层） |
| final-report.md | 每个 must 节点的 answer_pointer 指向报告章节 | must 节点 answer_pointer 非空 |

## 5. 执行流程（5 轮探索）

由 intent_discovery.py 的 prompt 模板驱动，Agent 逐轮执行并 commit：

1. **R1 字面记录**：用户说了什么（stated）
2. **R2 差距挖掘**：嘴上说的 vs 实际要的（gap，可为"无显著 gap"）
3. **R3 意图树构建**：产出 intent_tree（L0-L4 分层节点）+ 元问题 + 第一性原理拆解
4. **R4 路径生成**：产出 candidate_paths（≥2）+ 初步选择理由
5. **R5 问题说明书**：固化核心问题（可解/可验证/可批评）+ 概念阶梯种子 + ≤3 个阻塞性澄清问题 + success_criteria

finalize 硬校验（工具机械执行）：
- 5 轮全部 commit 才允许 finalize
- intent_tree 非空、含 ≥1 个 L1_meta 节点、≥3 个 L2 节点
- candidate_paths ≥2 且恰 1 个 selected
- blocks_plan_if_unanswered=true 的澄清问题 ≤3
- success_criteria 非空

---

## 6. 反僵化条款

意图树是**活的**。允许在调研中途修订（新发现推翻元问题），但：
- 修订必须追加 `revision_history`（旧树快照+修订理由+触发证据），禁止原地改
- 修订 L1 元问题 = 重大方向变更，必须重过 step_1.5 方向选择
- 修订 L2/L3 节点 = 常规迭代，记录即可

## 7. 与其他协议的关系

- **step_1.5 方向选择（20-方向选择协议）**：边界问题打在本协议的路径分叉上
- **step_3 调研方案**：子问题矩阵引用树节点，无引用视为模板填空
- **step_7.5 行文思路规划（23）**：archetype 选择受意图树认知类型影响
- **step_9 报告**：每个 must 节点在报告中有落点（answer_pointer）
- **step_11 溯源清单**：结论 → 假设 → 证据 → 树节点 的完整链路
