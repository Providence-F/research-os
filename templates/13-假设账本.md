# 假设账本模板

> 假设账本记录判断如何生成、降级、反转或确认。深度研究不是堆信息，而是让判断在证据和反方攻击中持续修正。

## 1. 使用场景

R2/R3 项目必须维护假设账本。

尤其适合：

- 产品机制判断
- 公司 / 岗位优先级判断
- 选题 / 导师 / 作品集决策
- 行业趋势判断
- 用户需求洞察

## 2. JSON 文件位置

```text
03-evidence/hypothesis_ledger.json
```

## 3. 字段规范

```json
{
  "schema_version": "research-os-hypothesis-ledger-v0.3",
  "project_name": "",
  "hypotheses": [
    {
      "id": "H001",
      "hypothesis": "",
      "status": "active / confirmed / downgraded / rejected",
      "confidence": "low / medium / high",
      "supporting_evidence": [],
      "contradicting_evidence": [],
      "revision_history": [
        {
          "from": "",
          "to": "",
          "reason": ""
        }
      ]
    }
  ]
}
```

## 4. 质量要求

- R2/R3 至少要有 3 条假设。
- 至少 1 条假设必须被降级、修正或反方攻击过。
- 强结论不能只出现在最终报告里，必须能追到假设账本和证据矩阵。
- `revision_history.reason` 必须写清为什么改，不要写“优化表达”。

## 5. 状态含义

| status | 含义 |
|---|---|
| active | 当前仍在验证 |
| confirmed | 证据足以支持进入结论 |
| downgraded | 原判断过强，已降级 |
| rejected | 被证据或反方推翻 |

## 6. 与 red team 的关系

Red team 不是最后写一段批评，而是要回写假设账本：

```text
red_team.md -> downgraded/rejected hypotheses -> final-report.md
```
