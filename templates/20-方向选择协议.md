# 步骤 1.5：方向选择协议（Kimi 式）

> v1.3 新增强制步骤。在意图识别（步骤 1）完成后、任务卡（步骤 2）创建前必须执行。
> 没有此步骤的产物，任务卡不能创建。
> 适用范围：R2/R3 深度调研强制，R0/R1 可选。

---

## 1. 为什么需要这一步

深度调研最大的浪费不是"做错了"，而是"方向错了却做完了"。

当前系统的任务卡确认点（步骤 2）是"二选一"——Agent 产出完整方案，用户只能 yes/no。这有两个问题：
1. **成本不对称**：Agent 投入了完整方案设计，用户否决后成本沉没
2. **纠偏太晚**：方向错误在方案阶段才发现，已经走了一步

Kimi 式方向选择把确认点前置：Agent 给出 2-3 个方向，用户选择+修正，Agent 再进入任务卡。方向选择比方案评估更便宜，纠偏更早。

---

## 2. 执行流程

### 步骤 1：Agent 基于意图识别输出方向

Agent 读取 intent_doc.json，基于意图探索结果，输出 2-3 个研究方向。

每个方向必须包含：
- **方向名称**：一句话概括
- **核心问题**：这个方向要回答什么
- **研究路径**：大致怎么研究（不需要细节）
- **预期产出**：最终报告会包含什么
- **深度建议**：R0/R1/R2/R3 建议
- **方向风险**：这个方向可能跑偏到哪

### 步骤 2：用户选择或修正

用户收到方向后：
- 选择一个方向（最低成本）
- 或选择一个方向并修正（中成本）
- 或否决所有方向并提供新方向（高成本，但比方案阶段否决便宜）

### 步骤 3：Agent 基于选定方向创建任务卡

Agent 只能基于用户选定的方向创建任务卡，不能自行切换方向。

---

## 3. 产物文件

产物：`00-task/direction_selection.json`

格式：

```json
{
  "schema_version": "research-os-direction-v1.0",
  "project_name": "项目名",
  "created_at": "2026-07-12",
  "directions_proposed": [
    {
      "id": "D1",
      "name": "方向名称",
      "core_question": "核心问题",
      "research_path": "研究路径",
      "expected_output": "预期产出",
      "depth_suggestion": "R2",
      "direction_risk": "方向风险"
    }
  ],
  "user_selection": {
    "selected_direction_id": "D1",
    "user_modification": "用户修正内容，无则留空",
    "selected_at": "2026-07-12"
  },
  "status": "direction_confirmed"
}
```

---

## 4. 验证规则

- 产物文件必须存在：`00-task/direction_selection.json`
- `directions_proposed` 必须有 ≥2 个方向
- `user_selection.selected_direction_id` 必须非空
- `status` 必须为 `direction_confirmed`
- R2/R3 深度调研时，任务卡创建前必须存在此产物

---

## 5. 与其他步骤的关系

- 前驱：步骤 1（意图识别）
- 后继：步骤 2（任务卡）
- 没有此产物（R2/R3），步骤 2 不能开始
- 验证脚本检查此文件存在 + 字段完整性

---

## 6. 成本控制

- 方向选择只增加 1 轮用户对话
- 但可能节省 15+ 轮的错误方向研究
- 对 R0/R1 不强制（成本低，错了重来也快）
- 对 R2/R3 强制（成本高，方向错误代价大）
