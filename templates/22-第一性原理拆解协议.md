# 第一性原理拆解协议（v1.4 修订）

> v1.3 新增。解决"报告沦为数据罗列，缺乏本质拆解"的整链缺失问题。
> v1.4 修订：修正第一性原理的位置——从"对象介绍前"移到"对象介绍后"。
> 此协议贯穿意图识别、任务拆解、内容规划三个环节。

---

## 1. v1.4 修订说明

### v1.3 的问题

v1.3 要求"在呈现数据前，先用 ≥3 条不可再分的底层逻辑解释'这件事为什么会发生'"。

这个要求被误解为"在介绍对象前就讲第一性原理"，导致：
- 读者还不认识对象（不知道 Manus 是什么），就被抛入"为什么 Manus 会存在"的抽象推理
- 这是逻辑上的"前置依赖缺失"——讲"为什么存在"前，读者必须已知道"是什么"

### v1.4 的修正

v1.3 原意是"在给出判断和决策前，先讲底层逻辑"（即判断前先讲本质），但被误解为"在介绍对象前就讲本质"。

v1.4 修正措辞：把"在呈现数据前"改为"**在给出判断和决策前**"，消除语义歧义。

同时，第一性原理的具体位置由 step_7.5 的 narrative-plan.md 动态决定，不再固定在 §2.5。

---

## 2. 为什么需要这个协议

v1.2 的问题是：第一性原理被当作"语义质量"交给 Agent 自觉，而非"结构性要求"可被机械验证。

结果：报告是否有第一性原理，完全取决于 Agent 个体能力，而非系统保障。

v1.3 的解决思路：
1. **结构要求**：三个环节都增加第一性原理必填字段（可机械检查"有没有"）
2. **对抗测试**：subagent 尝试"再分"每条原理（可机械检查"真不真"）
3. **组合保障**：结构保证"有"，对抗保证"真"

v1.4 增强：第一性原理的位置也由 narrative-plan.md 规划，确保在读者建立基础认知后才讲抽象本质。

---

## 3. 三层结构要求

### 层 1：意图识别层

`intent_doc.json` 新增 `first_principles_decomposition` 字段：

```json
{
  "first_principles_decomposition": [
    {
      "id": "FP1",
      "principle": "出海是因为国内付费意愿低（海外5倍）",
      "irreducibility_argument": "付费意愿由消费习惯+支付基础设施+文化心理决定，这些是底层社会结构，不可再分",
      "evidence_basis": "Manus创始人肖弘公开陈述+Stripe报告"
    }
  ]
}
```

要求：
- ≥3 条不可再分的底层逻辑
- 每条必须有 `irreducibility_argument`（为什么不可再分）
- 每条必须有 `evidence_basis`（证据基础）

### 层 2：任务拆解层

`01-plan/research-plan.md` 的"元问题"section 必填且验证。

元问题必须回答：
1. 用户问的是不是正确问题？
2. 如果不是，正确问题是什么？
3. 这个问题成立需要哪些前提为真？

### 层 3：报告层

`07-output/final-report.md` 必须包含"第一性原理"章节。

要求（v1.4 修订）：
- **位置**：在读者建立基础认知之后（对象介绍+核心机制+竞争位置之后），在给出判断和决策之前
- **位置由 narrative-plan.md 动态决定**，不再固定在 §2.5
- 用 ≥3 条不可再分的底层逻辑解释"这件事为什么会发生"
- 章节标题必须包含关键词：第一性原理 / 本质 / 为什么 / 底层逻辑
- 每条原理后必须有"对你的含义"（拉回用户决策场景）

## 4. 对抗测试（组件C 的特化应用）

在步骤 9.6（对抗式审核）中，subagent 对第一性原理章节执行"再分测试"：

**再分测试规则**：
- 对每条"不可再分"的原理，subagent 尝试"再分"
- 如果能再分（拆成更底层的子原理），说明不是真第一性原理
- 主 Agent 必须回应：要么承认并重写，要么反驳"为什么不可再分"

**再分测试示例**：
- 主 Agent 写："出海是因为国内付费意愿低"
- subagent 攻击："付费意愿低可以再分为消费习惯+支付基础设施+文化心理"
- 主 Agent 回应选项：
  - 修改："修正为——出海是因为消费习惯（免费文化）+支付基础设施（信用卡普及度）+文化心理（为虚拟商品付费的意愿）三个不可再分的底层因素"
  - 反驳："消费习惯和付费意愿是同义反复，不是再分；支付基础设施是技术问题，可被解决，不是底层逻辑"

---

## 5. 验证规则

### 意图层验证
- `intent_doc.json` 必须含 `first_principles_decomposition` 字段
- 字段必须是 list，长度 ≥3
- 每项必须含 `principle`/`irreducibility_argument`/`evidence_basis`

### 任务层验证
- `research-plan.md` 必须含"元问题"section
- 元问题 section 字符数 ≥200

### 报告层验证（v1.4 修订）
- `final-report.md` 必须含"第一性原理"/"本质"/"为什么"/"底层逻辑"关键词的章节
- 该章节字符数 ≥500
- **v1.4 新增**：该章节必须在"调研对象到底是什么"章节之后（位置检查）
- **v1.4 新增**：`narrative-plan.md` 必须声明第一性原理的位置

### 对抗测试验证
- `adversarial_review.json` 必须含 type 为 `first_principles` 的攻击
- 主 Agent 必须对该攻击有回应

## 6. 与其他协议的关系

- 本协议定义"什么是第一性原理"和"怎么检查"
- `20-方向选择协议.md` 确保方向正确（方向错了，第一性原理也白拆）
- `21-对抗式审核协议.md` 执行"再分测试"（对抗测试的具体应用）
- `23-行文思路规划协议.md`（v1.4 新增）决定第一性原理在报告中的位置
- 四者配合：方向对 → 原理拆解 → 位置规划 → 对抗验证
