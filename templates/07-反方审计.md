# 反方审计

> 反方审计不是装饰。如果没有导致任何结论降级，说明审计没用力。

## 1. 问题框架是否错了

> 思考型决策任务必须先攻击问题本身。不能只问证据够不够，还要问这个问题值不值得按当前方式回答。

| 当前问题 | 可能错在哪里 | 如果反方成立，报告应如何改 |
|---|---|---|
| 例：选哪个毕业论文导师最适合长期方向 | 真问题可能不是选谁，而是毕业论文是否值得高投入 | 从“导师排名”改成“投入策略 + 导师选择” |
| 例：做哪个作品集项目 | 真问题可能是当前阶段不该再开新项目 | 增加“不做 / 延后 / 最小版本”的策略 |
|  |  |  |

## 2. 投入产出是否被高估

| 建议 | 可能被高估的收益 | 被低估的成本 | 降级方式 |
|---|---|---|---|
| 例：认真做成战略资产 | 面试官未必看，成果可能不可展示 | 时间、流程、协作、窗口期 | 降级为轻资产化或保底完成 |
|  |  |  |  |

## 3. 用户是否在自我合理化

| 用户叙事 | 可能的自我说服 | 需要补的现实检验 |
|---|---|---|
| 例：这个题能服务就业 | 可能只是把低价值任务包装成作品集 | 目标岗位是否真的看、能否变成可演示产出 |
|  |  |  |

## 4. 证据不足的结论

| 结论 | 问题 | 建议处理 |
|---|---|---|
| 例：C007 客户覆盖头部品牌 | 客户名单来自 MiMo 搜索汇总，未拿到官网案例页或独立媒体原文 | 降级为 C/E，标待验证，不作为核心决策依据 |
|  |  |  |

## 2. 可能误匹配的信息

| 信息 | 为什么可能误匹配 | 当前处理 |
|---|---|---|
| 例：某公司客户名单包含大厂 | 可能是子业务合作、历史客户、生态伙伴，被汇总成集团客户 | 要求原文核验；未核验前不写成事实 |
|  |  |  |

## 3. 推断冒充事实的地方

| 表述 | 实际证据 | 修正写法 |
|---|---|---|
| 例：产品已经形成护城河 | 只有功能描述，没有留存、客户续费、技术壁垒证据 | 改为"可能形成差异化，护城河待验证" |
|  |  |  |

## 4. 来源不独立的地方

| 信息点 | 来源 | 问题 |
|---|---|---|
| 例：融资金额 | MiMo 汇总 + 多篇媒体 | 多篇媒体可能都转载同一篇 PR 稿，不算独立来源 |
| 例：客户规模 | 官网 + AIHub 工具页 | 工具页可能复制官网描述，不算独立来源 |
|  |  |  |

## 5. 信息稀缺下的叙事填充

> Kimi 启发：6 个 Agent 也救不了 5 份 JD + 1 段公司介绍。信息稀缺时，Agent 数量增加可能只是增加叙事复杂度，不增加准确性。

| 叙事部分 | 实际证据支撑 | 是否过度填充 | 处理 |
|---|---|---|---|
| 例：完整商业模式分析 | 只有招聘 JD 和官网一句话介绍 | 是 | 收敛为"商业模式待验证"，不强写定价/销售漏斗 |
|  |  |  |  |

## 6. Agent 是否过度自信

> 检查 Agent 产出是否假装有把握。置信度低于 50% 的判断必须显性标注，不能堆叙事掩盖。

| Agent 产出 | 实际置信度 | 是否过度自信 | 修正 |
|---|---|---|---|
| 例："值得重点投递" | 中低：产品机制和客户名单都未实测/未核验 | 是 | 改为"值得关注，待 demo 实测和客户核验后决定优先级" |
|  |  |  |  |

## 7. 反方攻击路径

如果我是反方，我会这样攻击这份报告：

1. 例：你的关键客户名单是单源汇总，可能全是 PR 稿传抄。
2. 例：你把产品官网话术当成实际能力，没有 demo 实测。
3. 例：你的方法论映射是自我说服，产品团队未必真的按这个方法论做。

## 8. 需要降级的结论

| 原结论 | 原等级 | 新等级 | 原因 |
|---|---|---|---|
| 例：值得重点投递 | 中高 | 中/待验证 | 关键证据未核验，结论强度过高 |
|  |  |  |  |
