# 候选池模板

> 候选池不是来源清单。它是研究执行前半段的“召回—筛选—淘汰”账本，用来防止搜到什么就写什么。

## 1. 使用场景

R2/R3 项目必须维护候选池。

候选可以是：

- 网页来源
- 用户提供文件
- 搜索结果摘要
- 数据库记录
- 公司 / 导师 / 岗位 / 产品 / 竞品对象
- 访谈材料或用户评论集合

## 2. JSON 文件位置

```text
02-sources/candidate_pool.json
```

## 3. 字段规范

```json
{
  "schema_version": "research-os-candidate-pool-v0.5",
  "project_name": "",
  "items": [
    {
      "id": "S001",
      "title": "",
      "url_or_path": "",
      "source_type": "official / media / social / database / user_file / search_summary / object",
      "claim": "",
      "expected_use": "",
      "evidence_grade": "A-F",
      "independence": "independent / copied / unknown / user_provided",
      "status": "candidate / accepted / discarded / conflict",
      "discard_reason": ""
    }
  ]
}
```

## 4. 质量要求

- 至少要有候选被丢弃，否则说明筛选不够用力。
- 搜索摘要默认 C 级，不能直接支撑强结论。
- 用户文件可以是 A 级事实来源，但不能自动推出判断。
- `discard_reason` 必须写具体原因，不能写“无用”。

## 5. 与其他文件的关系

```text
candidate_pool.json -> accepted items -> evidence_matrix.md
candidate_pool.json -> discarded items -> discarded.md
candidate_pool.json -> conflict items -> conflicts.md
```
