Research OS

一个用于发现和填补知识盲区的深度调研系统。
把 LLM 的生成能力转化为可追溯、可审计的研究工作流。

Research OS 把深度调研拆解成 16 个步骤和 8 个质量门禁，通过三权分立机制让调研过程白盒化。系统采用 Smart Agent. Dumb Tools. 设计哲学，已迭代至 v1.4，累计产出 20+ 份深度调研报告。

产品概览

这是什么

Research OS 是一套深度调研工作流系统。输入一个调研主题，系统会走完从方向选择、候选源采集、证据矩阵、反方审计到最终报告的完整流程，每一步都有明确的输入输出和质量检查点。

和直接用大模型做调研的区别在于：每一段结论都能溯源到来源，每一个假设都记录了置信度，每一个核心判断都经过独立审计 Agent 的攻击验证。整个研究过程是白盒的，读者可以独立验证任何一个环节。

做这个产品的原因

现有工具解决不了的问题

这个产品起源于我自己做调研时遇到的困难，以及排查现有工具后发现的缺口。

直接使用体验
Kimi Deep Research 的局限
  • 高质量产出强依赖提示词设计，使用门槛在用户侧
  • 绑定 Kimi 网页端生态，通过 API 调用时质量不可控
  • 产出偏论文风格，可读性弱
开源工具排查
开源 Deep Research 工具的缺口
  • 部分工具内部流程黑盒，交叉验证和反向审计不足，数据可信度低
  • 部分工具仍需精心设计提示词，且缺少意图识别模块
核心痛点
知识盲区的发现问题
  • 做调研时经常不清楚自己有哪些知识盲区
  • 例如面试涉及 B2B 产品知识框架、SaaS 权限分级等，事先并不知道自己缺这些知识
  • 现有工具都假设用户能提出明确问题，但知识缺口往往在提问之前

这三个层面的问题指向同一个需求：需要一个能帮助发现知识盲区、且研究过程可追溯的调研系统。现有工具在这个需求上都有缺口，这是做 Research OS 的直接原因。

设计哲学

Smart Agent. Dumb Tools.

这个原则是在迭代过程中形成的，不是一开始就设计好的。

系统初版采用大量模板和规则约束 Agent 产出。实际使用中发现，规则越多，Agent 越容易找到绕过规则的方式，产出质量反而下降。每增加一条规则，都会被 Agent 以非预期的方式规避。

这里存在一个矛盾：从第一性原理拆解技术栈时，要求 Agent 有自主推理和判断能力；但在工具层面堆叠规则要求 Agent 机械遵守，又是在压制这种能力。两者在方向上冲突，产出质量受制于这个矛盾。

原则
工具只做机械检查，语义判断交给 Agent
工具只执行单一功能：存在性检查、字数统计、格式校验、字段值非空、正则匹配。所有涉及"好不好、要不要重写、质量高低"的判断由 Agent 推理完成。工具不硬编码项目特定信息，不用阈值做语义决策。

这个原则和 Kimi 等端到端产品的思路不同。Kimi 在预训练和后训练阶段完成 Agent 调教，推理时不需要外部框架约束。Research OS 作为工作流系统，无法干预模型训练，因此在工具层保持简单，把推理空间留给 Agent。

这个方向调整后，工具维护成本下降，Agent 产出质量回升。后续的迭代都围绕这个原则展开：发现工具做了语义判断就重构，发现规则可以被绕过就简化而不是加规则。

系统设计

工作流与质量门禁

Smart Agent. Dumb Tools. 原则落地为三个机制：三权分立、16 步工作流、8 个质量门禁。

机制一
三权分立
  • 调研 Agent（生产权）：负责生成内容
  • 独立审计 Agent（验证权）：负责质疑结论，与生产 Agent 隔离
  • 工具（记录权）：只做机械检查，不做语义判断

Agent 不能审计自己的产出，工具不能越权做语义判断。

机制二
内容与美学规范
  • 内容层面：每段结论可溯源到来源和推理链
  • 美学层面：Anthropic 米色风格、Lora 衬线正文、结构化块穿插
  • 目标：产出本身有可读性，支持后续迭代

8 个质量门禁（核心四个）

方向选择门禁
深度调研必须完成 Kimi 式边界追问
防止调研范围过宽或过窄
行动方案门禁
行动方案占报告比例 >= 15%
防止只分析不行动的倾向
对抗式审核门禁
对第一性原理执行再分测试，攻击数量 >= 3
确保核心原理不可再分，结论经过压力测试
独立审计门禁
5 问结构化检查
Agent 不能审计自己的产出

这些门禁都是机械检查：工具只验证"有没有"、"够不够数"、"格式对不对"，不判断"好不好"。质量判断交给 Agent 和独立审计环节。

迭代历程

从 v0.1 到 v1.4

系统的演进由实际使用驱动，没有预设路线图。每发现一个产出问题就迭代一轮。

v0.1 — v0.3（2026-07-02）
项目脚手架与第一份报告
建立项目目录结构、任务卡模板、候选源采集流程。产出第一份报告，验证基本可行性。核心问题：输出不可信、过程不可追溯。
v0.4 — v0.6（2026-07-03 ~ 07-04）
引入证据矩阵与独立审计
新增证据矩阵、假设账本、核心对象直采协议、独立审计 Agent。第一次让调研质量可被机械检查。发现问题：Agent 自说自话，缺少反方视角。
v0.7（2026-07-05）
Smart Agent. Dumb Tools. 原则确立
经过初版堆叠规则失败的实践，确立工具只做机械检查、语义判断交给 Agent 的原则。修复 2 处违规（硬编码产品名）。通用 HTML 构建器上线。
v1.0 — v1.1（2026-07-09 ~ 07-10）
行动方案门禁与 HTML 结构检查
新增行动方案比例检查（>=15%），解决报告只分析不行动的问题。HTML 构建器增加 9 项结构检查，确保美学规范落地。
v1.2 — v1.3（2026-07-11 ~ 07-12）
方向选择协议与对抗式审核
新增 Kimi 式边界追问方向选择协议、对抗式审核协议、第一性原理三层检查。调研结论从 Agent 主观判断升级为经过攻击验证的存活结论。
v1.4（2026-07-12 ~ 07-15）
行文思路规划与三级节点提纲法
新增 step_7.5 行文思路规划，章节按认知递进组织。删除低价值人工确认点，改为 Agent 自主加独立审计验证。

到目前为止系统已产出 20+ 份深度调研报告，每份报告都经过反方审计、独立审计和对抗式审核。每发现一个产出问题就迭代系统本身，累计约 20 轮迭代。
