这个系统怎么运作

v1.0 流程：前 3 步防止方向错（意图探索+降秩），中间 3 步收集和验证证据（含核心对象直采），最后 4 步确保报告可信且能被读者读懂（独立审计+读者模拟+信任账本）。

第 1 步
创建项目
ros new
起调研任务，设定深度和模式，生成 intent_doc 骨架
第 2 步
意图探索
Agent 3轮探索
宽泛探索→挖差距→固化问题说明书。Agent 提交真实结果，工具不做伪信任注入
第 3 步
任务卡 + 降秩
Agent
填 task-card + 用 ljg-rank 降秩核心生成器写入 research-plan.md
第 4 步
收集证据
Agent
候选源筛选、证据矩阵、假设账本（含置信度追踪）
第 5 步
核心对象直采
Agent
直接检查核心对象（产品/JD/技术栈），记录真实发现
第 6 步
分析 + 红队
Agent
深度分析 + 反方审计（主动攻击自己的结论）
第 7 步
写报告
Agent
读者优先报告模式：已知→桥梁→未知的认知阶梯结构
第 8 步
独立审计
Agent
独立审计 Agent 检查强论断溯源率，不参与写作只负责审计
第 9 步
读者模拟
Agent
LLM 扮演读者逐段读，读懂了才交付。写-读-改闭环
第 10 步
溯源 + 验证
ros build
生成 trace-manifest + view-model + HTML，跑 validate + meta_validator + trust_ledger

为什么这样设计

7 条核心原则，前 3 条是 v1.0 第一性原理重构新增——信任转化器、Smart Agent Dumb Tools、四权分立。

信任转化器
系统本质是把不可信的 AI 认知劳动转化为人类敢拿真实后果下注的决策输入。每条产出都要回答：这个结论的信任分是多少？
Smart Agent. Dumb Tools.
工具只做机械检查（文件存不存在、字段非空、字符数够不够），语义判断全部交给 Agent。工具不硬编码产品名，不做关键词路由。
四权分立
研究 Agent（生产）+ 审计 Agent（攻击）+ 工具（机械验证）+ 元审计层（审计工具自身）。四权互相制衡，任何一方作弊都会被其他方检出。
可溯源
每条结论都能追溯到证据。不是'我觉得'，是'证据显示'。trace-manifest.json 记录每个 claim 的证据链。
读者优先
报告写给读者看，不是写给研究者自己看。幕后信息不进正文。reader_simulation 逐段验证可读性。
反方审计
每条核心结论必须经过反方攻击。R2 深度要求至少降级 1 个结论。独立审计 Agent 不参与写作，只负责审计。
信任账本
5 环信任链加权打分：意图探索(0.20) + 核心生成器(0.15) + 独立审计(0.20) + 读者模拟(0.15) + 状态产物一致性(0.30)。>=0.7 才能 decision_ready。

信任账本（Trust Ledger）

每个调研项目都有 5 环信任链加权打分。>=0.7 才能 decision_ready（敢拿真实后果下注）。跑 python meta_validator.py --project <项目> --trust-ledger 生成。
